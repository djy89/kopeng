# Changelog

All notable changes to KOPENG are documented here. This project adheres to [Semantic Versioning](https://semver.org).

## [Unreleased]

### Added
- **`is_locked` write path**: `PUT /api/memories/:id` and the MCP `update_memory` tool can set the Hard Anchor directly (snapshot-first, byte-identical writes are no-ops). The lock **is** captured in `memory_revisions` and restored by rollback (SQLite v10 / PG v12) — without that, a model-issued `update_memory {locked:false}` was unrecoverable and unrecorded, and the row became archivable on the next pass while the README still promised every write was reversible. The new column is nullable with **no default**, deliberately: backfilling pre-migration revisions with "was unlocked" would make the restore `COALESCE` strip real anchors on rollback, so `null` (predates the migration) stays distinguishable from `false`. Note the consequence — rolling back to a revision taken while the row was unlocked now clears a lock applied afterwards, exactly as it already reverts a later scope/type change.
- **`npm run migrate:anchors` / `kopeng migrate-anchors`**: audited driver (dry-run default) that locks every active memory still anchored only by a deprecated spelling (`confidence >= 1.0` or `metadata.pinned`), via one `PUT` per row. Ships as a real CLI subcommand as well as an npm script, because `doctor`'s legacy-anchor warning is reachable on packaged installs where `scripts/ops` isn't in `files` and `tsx` is a devDependency — the npm-script form alone was a dead end there. `doctor` now detects which install it is and prescribes the form that actually runs. The driver resolves its `.env` through the standard `KOPENG_ENV_FILE > <repoRoot>/.env > ~/.kopeng/.env` tiering rather than a hardcoded repo path, which would have silently 401'd from inside `node_modules`.
- **`kopeng` CLI + npm packaging**: the repo is now publishable as the `kopeng` npm package — a real `bin` (`kopeng` -> `dist/cli/index.js`) dispatching `wire`/`doctor`/`canary`/`mcp`/`start`/`version`/`help` (at this point `uninstall`/`update`/`viz` were reserved, reporting "coming in this release" — `uninstall`/`update` shipped in Task 2.4, `viz` in Task 2.6, both below), the three ops commands (`wire-client`, `doctor`, `recall-canary`) moved into `src/cli/` so strict `tsc` compiles them, a canonical install-manifest module (`src/cli/manifest.ts`) backing init's consent screen, uninstall's summary, and README.md's "what it puts on your machine" table from one source (`tests/unit/install-manifest.test.ts` pins all three), and a `files`/`prepublishOnly` packaging setup pinned by a pack-contents test. The `files` list ships the whole `viz/` directory verbatim, including the two marketing-demo assets (`viz/demo.html`/`demo.js`, otherwise excluded from the public GitHub export) — npm can't cheaply exclude files-listed subpaths without enumerating the directory, and the assets are small and harmless.
- **User-level autostart + `kopeng ensure`**: two zero-admin-rights mechanisms that keep a packaged server alive across reboots and self-heal it between prompts. `kopeng autostart status|register|unregister` plans and applies a per-platform login-autostart entry — a Scheduled Task on win32 (falling back to a Startup-folder shim if `schtasks` fails), a `systemd --user` unit on linux (falling back to a "use `kopeng ensure`" note when there's no user systemd), and a LaunchAgent on darwin. `kopeng ensure` probes `GET /api/health` and, if nothing answers, launches a detached server and returns immediately with no readiness wait; a response that isn't KOPENG-shaped is treated as a foreign process on the port and never spawned over, instead writing `~/.kopeng/hints/ensure_conflict.json`, which `doctor` reads back and WARNs on while it's still fresh (<24h). The SessionStart hook fires `ensure` fire-and-forget via an optional `~/.kopeng/ensure.json` knob (written by `kopeng init`) — absent or malformed is a byte-identical no-op. A packaged install's `.env` now resolves via `KOPENG_ENV_FILE` (explicit) > `<projectRoot>/.env` (from-source, unchanged) > `~/.kopeng/.env` (new fallback, since a packaged install's project root never carries one).
- **`kopeng init`**: the one-command installer (preflight -> enumerated consent -> install app -> env -> models -> autostart -> start -> wire -> doctor+canary -> summary), mirroring `wire`'s dry-run-and-enumerate discipline across the whole install. Preflight checks Node 20+ (warns rather than blocks on the known win32+Node24 recall-hook issue, T52), probes the target port (default 3200; a foreign process on it auto-picks the next free port in 3201-3299, or fails plainly if `--port` was explicit), best-effort disk space, and which clients (`~/.claude.json`/`~/.codex`) and existing install are present. The consent screen renders `src/cli/manifest.ts`'s manifest verbatim, names the chosen learning profile, and states plainly that everything it lists is removed by `npx kopeng uninstall`; nothing is installed before the operator accepts (`--yes`/`--non-interactive --profile <p>` skip the prompt for scripted/CI installs — `--from <spec>` pins an install source ahead of the first npm publish). The embedding model downloads in the foreground with a progress line (`--offline` verifies a pre-populated model cache instead and fails naming what's missing), `.env` is written with absolute paths and append-only semantics on repair (an existing `ADMIN_API_KEY` is never touched), and the close prints `kopeng viz`'s URL — printed, never opened (RULING-F). Re-running `init` on an existing install is a repair: the pinned-version install is skipped, autostart/wire re-register idempotently, and no `.env` key is duplicated.
- **`kopeng uninstall` + `kopeng update`**: the symmetric reversal and the version-bump path, closing the promise `init`'s consent screen made. `uninstall` stops the server via a new admin-gated `POST /api/admin/shutdown` — but only after a **keyless `GET /api/health` confirms a KOPENG server is what is actually listening**; anything that answers wrong-shaped, or does not answer at all, gets no admin key and a printed reason instead. Without that probe, uninstalling or updating while a foreign process held the port would have handed it the key that gates every mutating endpoint, defeating the 0600 permission on `.env` without the attacker ever reading the file (the exact graceful-shutdown routine the SIGTERM/SIGINT handlers already use — `requestShutdown` awaits the full shutdown before exiting the process, so the CLI never races a still-running server for the app dir's native modules), waits for the port to actually go quiet before deleting the app dir (retrying the delete a few times — a residual native-module handle can take a moment to release), unregisters autostart (a malformed record is removed and reported rather than left on disk forever; the record is also no longer trusted blindly — commands must be one of `schtasks`/`systemctl`/`launchctl` and files must resolve under one of the four roots `planAutostart` can produce, and anything refused is reported and makes the command exit non-zero, so an uninstall that left a scheduled task behind can never report clean), removes the ensure knob, and reverses the Claude Code MCP/hook wiring (`wire-client.ts`'s new `removeClient` — the ownership-predicate-symmetric reversal of `mergeConfigs`, so foreign entries survive byte-identical); the database, downloaded models, and `.env` are kept unless `--purge` (gated behind `--yes` or a typed `purge` confirmation — the one destructive act here; refusing on non-interactive stdin without `--yes` exits non-zero rather than falsely claiming success; consent is no longer the only gate — `--purge` also requires the target to actually look like an install (`.env` plus `app/` or `data/`, sampled before the app dir is removed) and refuses by name otherwise, since `KOPENG_HOME` is a supported override and `--yes` skips the prompt that would have shown the path — `--force` bypasses the check). Every step degrades to a printed reason and continues rather than aborting — an unreachable/keyless/older server, a hand-edited client config, or a stray fs error are all handled — but the closing line and exit code are honest about it: "completed with issues" and non-zero whenever anything above didn't fully complete. `update` runs `npm install --prefix` for a newer release (`--from` overrides the spec) and, only when the installed version actually changed, waits for the old server to go quiet, restarts it (`kopeng ensure`), and consumes the resulting decision — a still-answering old server or a foreign process holding the port are reported plainly (non-zero exit) rather than racing straight into a misleading health/doctor read; an already-current install is a no-op.
- **Release workflow + install smoke**: `.github/workflows/release.yml` (tag `v*` or manual dispatch, separate from `ci.yml`) packs a release candidate once (`npm ci` -> build -> unit tests -> `npm pack`), proves the exact same tarball installs for real on five platforms (`ubuntu-latest`, `ubuntu-24.04-arm`, `windows-latest`, `macos-latest`, `macos-15-intel` — a genuine `npm install` into a sandbox, then `init`/`canary`/`uninstall --purge` against a fake `HOME` and port 3299, never the runner's real environment), then publishes to npm with `--provenance` behind an operator-approved `npm-publish` GitHub Environment (inert until the operator adds the environment + `NPM_TOKEN`, per RULING-D). The install proof is `scripts/ci/install-smoke.mjs` (node builtins only, pure helpers unit-tested in `tests/unit/install-smoke-helpers.test.ts`), which always names the failed step on a non-zero exit and always tries to stop any server it started before deleting its sandbox. `kopeng init`'s npm-install failure path also gained `diagnoseNpmFailure` (`src/cli/init.ts`): a plain-language paragraph — naming the likely cause (no prebuilt native binary for this platform/Node, or a missing build toolchain) and the two ways to fix it — instead of a raw node-gyp/MSBuild dump. Runbook: `docs/ops/release.md`.
- **`kopeng viz`**: launches the bundled web dashboard (`scripts/viz-server.js`) in the foreground — stdio inherited, Ctrl-C stops it, an explicit `--port <n>` or an already-set `VIZ_PORT` overrides the script's own default (`8780`) for both the spawn and the printed URL line. Closes the last `COMING_SOON` command from the Install Strategy roadmap.
- **README v2**: a full install-first rewrite — the `npx kopeng@latest init` one-command quickstart (Node 20+ the only named prerequisite) leads, followed by a "what it puts on your machine" table rendered from the same `INSTALL_MANIFEST` init's consent screen and uninstall's summary already use, and a new "Watch it think" section covering `kopeng viz`'s six-tab dashboard. The clone-and-`npm run wire` path moves to a "prefer to run from source?" pointer into SETUP.md. Carries forward RULING-A (no version numbers in prose) and the Windows VC++ Redistributable note from the prior README. SETUP.md gained a matching "npm-installed layout" subsection (`~/.kopeng/` app/data/models/logs/.env, the `.env` resolution order, `autostart`/`ensure`/`update`/`uninstall`), demoted the NSSM/systemd walkthroughs under a "run it as a proper service (operators)" heading (§3a/§3b, content unchanged), and added a short from-source Docker recipe (§3c, honest that no published image exists yet) and an offline-install note (`init --offline` + a copied `~/.kopeng/models`).

### Changed
- Version-story reconciliation: one version story — semver in `package.json`, surfaced at runtime by `GET /api/health` and by `doctor`'s server-vs-local skew check — with prose everywhere else standardized on "developer preview" (no version number).
- **`is_locked` is now THE Hard Anchor**: it freezes the read-time decay curve exactly like the `confidence >= 1.0` short-circuit. `confidence >= 1.0` and `metadata.pinned` are DEPRECATED anchor spellings — still honored this release, but `/api/ops/corpus-health` reports `legacy_anchor_count` and `doctor` warns toward `migrate:anchors` when it's nonzero.
- **Project scope is now derived from the git remote (RULING-C, WS7.6)**: `project:<basename(cwd)>` is replaced by `project:<owner>-<repo>` parsed from `.git/config` (pure fs, no `git` binary — gitless installs are supported per T57), so two repos named `api` under different owners no longer collide and two worktrees of one repo now land in the same scope. `.kopeng.json`'s new `project` key overrides the derivation per-directory; no usable remote falls back to `basename(cwd)`, byte-identical to before. All six hook/doctor call sites switched; existing corpora need a supervised migration (`docs/ops/scope-derivation-migration.md`) — expect **one orphaned old-basename session breadcrumb per active project** at cutover (inert, self-heals via the next session; sequence/trigger caches self-heal via TTL with no orphan at all).

### Fixed
- **Keyword-only mode now serves recall (T55)**: with the embedding model unavailable — still loading, or permanently failed (the Windows VC++/ONNX case) — `POST /api/memories/recall` no longer returns an empty list by explicit early return. Its FTS and staple-injection lanes are embedder-independent and now run on their own, so the per-prompt hook keeps surfacing keyword matches instead of nothing, matching what `/api/memories/search` already did in that state.
- **`/api/health` is honest about a degraded server (T56)**: an embedding-model load that has terminally failed is now a distinct state rather than a cold start that never ends — health reports `status: "degraded"` / `embedding: "error"` / `search: "keyword_only"`, so "up but keyword-only" is visible instead of looking like a server still warming up. The transient mid-load shape (`loading`/`initializing`) is unchanged.
- **`npm test` no longer fails on an install without `git` (T57)**: `git` is not a declared dependency, so downloading the repo as a ZIP rather than cloning it produced a red suite (`spawnSync git ENOENT`, reported twice) on an otherwise healthy install. The git-dependent hook-contract cases are now reported as skipped when `git` is absent and still execute wherever it is present, and their teardown no longer turns one setup failure into two.

## [1.1.0] — 2026-08-22

Scope identity, audited curation, and release posture — the 0.x preview program (Phases 0–8) plus the recall-reliability sprint that preceded it. No breaking API changes; all additions are additive or fail-open.

### Scope identity
- **Anchor-marker scopes**: a `.kopeng.json` marker lets a directory declare its scopes explicitly (`{ "scopes": ["client:acme", ...] }`); the recall hook walks up from `cwd`, merges declared scopes onto the base pair — purely additive, fail-open, bounded.
- **Scope-alias layer**: an operator-curated alias table (in `operator_config`, never a tracked file) with write-time canonicalization at every write site, read-time alias-group expansion on recall/search/surface, a read-only alias-draft proposer, and an audited bulk re-scope migration driver (dry-run default, one audited PUT per row, residual check).
- **One shared scope definition** (`src/scopes/resolver.ts`): a single validated, versioned resolution consumed by the write path, the drift detector, and the migration driver — with explicit rejection classes (self-map, chain, malformed scope, generic capture) and a composition test that fails if any consumer grows its own parser again.
- **Scope registry & minting**: a `scope_registry` table records each scope's provenance; new scopes are minted, name collisions are quarantined (`--q<n>`) — writes always land, never merge or block; scopeless writes route to a `project:_unrouted` triage scope instead of silently leaking to `global`; malformed scopes are captured with the raw preserved, never rejected.
- **Honest discovery watermarks**: per-scope run rows record per-scope end ids; ephemeral scopes are `held` (not silently skipped) and releasable via an operator ruling + time-preserving admin re-drive that creates no observations and rewrites no timestamps.
- **Drift visibility & rulings**: `GET /api/ops/scope-drift` (new-variant detection with per-variant evidence), `GET /api/ops/scope-registry`, and `POST /api/admin/scopes/rule` (confirm / merge_into / rename, with tombstones so freed quarantine suffixes are never re-minted).
- **One definition of "archived"** (`isArchived` / `ARCHIVED_SQL_PREDICATE`) plus a read-only reconcile reporter for legacy divergent rows.

### Curation — audited and reversible throughout
- **Every automated archive is audited**: promotion decay archival and both discovery-maintenance archive sites now route through the dream apply path (snapshot → archive → audit, compensate on failure) and honor the same operator gate; without audit dependencies they withhold rather than archive.
- **One archive-line predicate** (`isDecayedAtRisk`) shared by promotion, the dream decay tier, maintenance, and the corpus-health panel — set-equality across all four pinned by a composition test with a grep-guard against re-drift.
- **Hard Anchor contract completed**: `metadata.pinned` is honored by every archiver (previously promotion-only — dreaming/maintenance could archive a pinned row; RED-proved and closed).
- **Deterministic guards ahead of the LLM classifier**: referent guard (same-template/different-referent discovery pairs), numeric-divergence guard (changed values become supersessions, not duplicates), retirement-narration guard (self-narrated supersessions record their chain) — template noise never reaches the reasoner, and nothing a reasoner touches can auto-apply.
- **Reversibility done right**: `PUT /api/memories/:id` snapshots on every effective mutation; revisions capture scope/type/last_seen; rollback restores and *rescues* (reinforces, so a restored memory isn't immediately re-archived); revision retention with admin-gated reads and deliberate purge routes.
- **Maintenance scope promotion reworked**: audited re-scope of the best original to `global` (reversible, compensating on mid-group failure), gated OFF by default.

### Release posture & security
- **First-run posture**: `ADMIN_API_KEY` auto-generated into `.env` (atomic, owner-only); a non-loopback bind without both keys refuses to boot; loopback bind default.
- **Every mutating endpoint** outside observation ingestion requires the admin key when set — core memory CRUD included; reads stay public so keyless recall hooks keep working.
- **Operational proof commands**: `npm run canary` (store → embed → semantic recall through the real recall hook), `npm run backup` / `restore:verify` (manifested, torn-write-safe backups verified as a corpus, not a file), `npm run heartbeats` (scheduled-task staleness), `npm run clean:client` (allowlisted client-state cleanup that can never touch the outage alarm).
- **Recall context fix**: hook output now ships model-visible context on `additionalContext` (the old `systemMessage`-only emit reached the operator's transcript but never the model); the full stdout shape of both hooks is pinned by tests.

### Harnesses that can fail
- The replay harness pins exact per-band-pair classifier counts and gates both selector boundaries from both sides; the effectiveness harness re-reads its own report and asserts the headline per lane; a dirty-corpus drill runs a live local LLM against planted mess under 11 hard gates; a Postgres executed-SQL suite runs real SQL against a pgvector container in CI (its first run caught a real PG-only production bug).
- Server wiring is probed through the real composed server (`composeServer()`), not a hand-rebuilt approximation.
- Test suite grew from ~800 to ~1,400 tests.

### Docs
- Documentation-truth pass over the architecture docs: every load-bearing claim inventoried; one false claim and eight overclaims corrected in place.

## [1.0.0] — 2026-07-27

Initial public release. KOPENG is a persistent, self-hosted memory system for LLM/agent clients, exposed over the Model Context Protocol (MCP, stdio) and a REST API (Fastify).

### Core
- Hybrid semantic + keyword search (Reciprocal Rank Fusion) over a local, quantized `all-MiniLM-L6-v2` embedding model, with an optional `ms-marco-MiniLM-L-6-v2` cross-encoder reranker — 100% local inference at runtime, no data egress (the opt-in `eval:seed` dataset generator is the one exception and says so).
- SQLite (default) or PostgreSQL + pgvector backend, selected by `DATABASE_TYPE` (Postgres is maintainer-only as of 0.x — see docs/postgres-maintainer.md).
- 19 MCP tools (store / search / recall / traverse / …) and a versioned REST API with a consistent `{ data, meta }` envelope, Zod validation, and rate limiting.
- Optional services, each feature-flagged and gracefully degrading: Neo4j (entity graph), Redis (ephemeral context), MinIO (artifact storage).

### Curation — the dreaming "Librarian"
- Autonomous, feature-flagged nightly consolidation: collapses duplicates, decays stale memories, and routes contradictions/supersessions for review. Deterministic-first — an optional local LLM only *classifies* pairs and is kept out of the write path. Every consolidation write that changes an existing memory is snapshot-first, audited, and reversible via `POST /api/memories/:id/rollback`; auto-apply is hard-restricted in code to the exact-duplicate and decay classes, both shipping OFF.
- Passive, zero-LLM learning from real tool-use via heuristic detectors (repeated tool+input, error→fix, hot files, recurring errors, A→B sequences), producing confidence-scored memories.
- Type-tuned confidence decay with structural floors and auto-crystallization of durable memories.

### Security
- Optional shared-secret auth on observation-write (`OBSERVATION_API_KEY`) and mutating operator (`ADMIN_API_KEY`) endpoints; loopback-first defaults; multi-layer secret scrubbing on ingested tool output. Threat model and known-non-reachable dependency advisories are documented in [SECURITY.md](SECURITY.md).

### Tooling
- Windows (NSSM) and Linux (systemd) service recipes, a live observation stream (SSE) with a D3 visualizer, and a zero-LLM replay harness as the consolidation regression net.
