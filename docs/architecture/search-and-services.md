# Search Pipeline & Optional Services

> Extracted verbatim from CLAUDE.md (2026-09-07).

### Search Pipeline

1. **Embedding** (`src/embeddings/embedder.ts`): `all-MiniLM-L6-v2` (384-dim, local ONNX via `@xenova/transformers`). Lazy-loaded after server starts accepting requests.
2. **Hybrid search** (`src/search/hybrid.ts`): Reciprocal Rank Fusion merging semantic (cosine) + keyword (FTS5/tsvector) results. Pre-filters by type/scope/tags via `getFilteredIds()`. **Phase 4 (T7):** `POST /api/memories/search` expands each requested scope to its alias group before filtering (`scopeAliases.expand` — recall parity; the MCP `search_memories` tool inherits it unchanged, being a pure HTTP client), pinned by `tests/unit/search-alias-expansion.test.ts`. `GET /api/memories` listing stays EXACT-match by default with the opt-in `expand=aliases` query param (one-shot merged view over the alias group; `expand` + `cursor` together ⇒ 400) — the exact default is load-bearing: the migration driver's residual check depends on it to prove a scope empty post-migration.
3. **Fast recall** (`POST /api/memories/recall`): Hook-optimized semantic search — no reranking, lower threshold (0.40), project-scoped. Falls back to `global` scope only (never cross-project — pinned by `tests/unit/scope-list-sanitization.test.ts`). Used by the per-prompt session hook for low-latency lookups. Scope matching is case-insensitive. **Hybrid-lite + staple injection (2026-06-10, previously documented only in SETUP.md §8):** the endpoint also runs FTS in parallel with the semantic query and RRF-merges (a keyword hit rescues a memory whose semantic score a long prompt diluted), and memories tagged `staple` whose `metadata.trigger_terms` match a whole-word token in the query are force-injected at score 0.99 — bypassing scope filtering and the semantic threshold, with the result cap grown by the staple count so injected staples don't evict semantic results (recall handler in `src/api/routes.ts`). Staples are identity-level facts and should be locked (`is_locked`) — THE Hard Anchor — so they can't decay; `confidence: 1.0` and `metadata.pinned` are deprecated anchor spellings, still honored this release. Note the injection is corpus-WIDE by design (the staple prefetch takes no scope filter) and `/api/memories/recall` is keyless — so a network peer who can reach the port can extract any staple by guessing its trigger terms; as with the admin-key paragraph below, the `127.0.0.1` bind default is the real control. The staple-injection path is covered by `tests/unit/staple-injection.test.ts` (Phase 8 — the "honest gap" is closed); SETUP.md §8 remains the operator guide and carries the manual verification recipe.
4. **Reranking** (`src/search/reranker.ts`): `ms-marco-MiniLM-L-6-v2` cross-encoder. Lazy-loaded on first search. Scores raw logits (range ~-12 to +10). The reranked path applies the same confidence pipeline as the non-reranked path: candidates are filtered by `min_confidence`/`include_discoveries` *before* the cross-encoder runs (saves calls), rerank logits are sigmoid-normalized and confidence-blended for final ordering, then the 70:30 discovery partition applies.


### Optional Services (Feature-flagged via env)

Each gated by `*_ENABLED=true` in `.env`, gracefully degrades if unavailable:

- **Neo4j** (`src/graph/`): Entity extraction from memory content → graph nodes/edges. `traverse_memory` MCP tool. REST: `POST /api/memories/traverse`, `POST /api/memories/:id/graph`, `GET /api/graph/stats`.
- **Redis** (`src/cache/`): Ephemeral context key-value store. `set_context`/`get_context` MCP tools. REST: `PUT /api/context`, `GET /api/context/:key`, `GET /api/context` (list all), `DELETE /api/context/:key`.
- **MinIO** (`src/storage/minio.ts`): S3-compatible artifact storage. `store_artifact`/`get_artifact` MCP tools. REST: `POST /api/artifacts`, `GET /api/artifacts` (list), `GET /api/artifacts/:key`, `GET /api/artifacts/url` (presigned), `DELETE /api/artifacts/:key`, `GET /api/storage/stats`.
- **Promotion pipeline** (`src/promotion/`): Decay scoring, duplicate consolidation, auto-archiving. Runs via `POST /api/admin/promote`, `npm run promote`, or (R5, when dreaming is enabled) nightly as the first step of the consolidation chain `promotion → dream` under one lock hold. **Duplicate archival is RETIRED (GATE 1, R11):** promotion only *detects and reports* duplicate candidates (>0.99 cosine, run-row counts/ops viz unchanged) — duplicate collapse is owned exclusively by the dream apply path; `archive_duplicates` on `POST /api/admin/promote` is rejected with 400. **Decay archival is opt-in (GATE 1):** a non-dry run still computes and reports everything but archives nothing unless `auto_accept_decay` is on — the nightly chain reads the flag from `operator_config`; manual runs must pass `archive_decayed` explicitly (default false; withheld candidates are reported as `withheld`, never as `archived`), and non-dry manual promotes run under the consolidation lock (R10, 423 when busy). **Decay archival is AUDITED (R14, GATE 1 fix):** the actual archive no longer diverges from the dream layer — promotion *selects* decay candidates with the SAME predicate as the dream `decay` tier — since Phase 4 that predicate has ONE name and one spelling, `isDecayedAtRisk` (`src/dreaming/scoring.ts`; threshold `DECAY_ARCHIVE_THRESHOLD = 0.2` in `src/discovery/confidence.ts`; durability-aware effective confidence; the old `shouldArchive` helper is deleted, and the old `computeDecayScores < 0.1` usage score now only drives run-row/ops reporting) and *routes* each archive through the dream apply path (`autoArchiveDecayed` builds `decay` diff entries on a real `dreams` row, calls `applyEntry`): snapshot to `memory_revisions` → archive → append `dream_audit_log` (compensate-unarchive on audit failure, invariant #11) → drop from the vector index, so every promotion decay archive is rollback-able via `POST /api/memories/:id/rollback`. Without a dream store an `archive_decayed` pass WITHHOLDS rather than archiving unaudited; the legacy `autoArchive` (un-audited, score-driven) is retained only for the D1.1 regression test and is off the promotion path. Decay score (D1.1 retune) is usage-gated multiplicative — `(0.7*recency + 0.3*frequency) * type/quality modifier` — used for reporting; `is_locked` (THE Hard Anchor) / `confidence>=1.0` / pinned (`metadata.pinned === true`) memories — the latter two DEPRECATED spellings, still honored this release — never decay or auto-archive; the Hard Anchor is the ONE `isAnchored` contract (`src/dreaming/scoring.ts`), re-checked at apply time, pinned by `tests/unit/anchor-contract.test.ts` + `tests/unit/decay-predicate-composition.test.ts`. (Before Phase 4 this sentence was FALSE for `metadata.pinned`: the pin was honored by promotion only, and dreaming/maintenance could archive a pinned sub-1.0 row — RED-proved and closed 2026-08-20.) Scope note (Phase 6): the anchor protects against ARCHIVAL — a pinned/locked sub-1.0 row's read-time effective confidence still ages for ranking (`computeEffectiveConfidence` takes no pin/lock input); of the anchor inputs, only `confidence >= 1.0` short-circuits the decay curve itself (the separate D1.1 dormancy freeze also returns stored confidence unchanged, on its own trigger). The recency anchor includes `last_seen`, so a recall rescues a memory from archival. **T30.3 auto-crystallization (Step 5, `src/promotion/crystallize.ts`):** the promotion pass also promotes durable memories (`observation_count>=10`, age>=7d via `created_at`, `confidence` in [0.6, 0.97), unlocked) to **0.97** ("sticky, not a Hard Anchor" — still decays slowly + supersedable) — snapshot-first → `updateConfidence`, REVISIONED and reversible (a `memory_revisions` snapshot, so rollback restores the prior confidence — note it appends no `dream_audit_log` row: it is not a dream apply), idempotent; **gated OFF** by the `operator_config.config.auto_crystallize` blob flag for the nightly, or run/preview on-demand via `POST /api/admin/promote {"crystallize":true}` / `{"dry_run":true,"crystallize":true}` (dry-run + no-dream-store WITHHOLD; a real run only RAISES confidence, never archives).
- **Auto-Discovery** (`src/discovery/`): Observation ingestion → pattern detection → confidence-scored memory creation. Two independent flags: `OBSERVATION_INGESTION_ENABLED` and `DISCOVERY_DETECTION_ENABLED`.
