# Auto-Discovery Pipeline

> Extracted verbatim from CLAUDE.md (2026-09-07).

### Auto-Discovery Pipeline

Observations (tool-use events) are ingested via REST API, stored in a **separate SQLite database** (`observations.db`), and periodically analyzed by heuristic detectors to create auto-discovered memories.

- **Observations DB** (`src/database/observations-db.ts`): Separate file from `memory.db` — different lifecycle, independent WAL/VACUUM, no lock contention
- **Observation store** (`src/database/observation-queries.ts`, `pg-observation-queries.ts`): Implements `IObservationStore` interface
- **Secret scrubber** (`src/utils/scrubber.ts`): Multi-layer (keyword + format-based) applied server-side as Fastify preHandler
- **Heuristics** (`src/discovery/heuristics.ts`): 6 zero-cost detectors (repeated tool+input, error-fix, hot files, repeated commands, recurring errors, sequences). Ephemeral inputs (temp paths, task outputs, plan files) are filtered out. Self-referential tools (`ToolSearch`, `mcp__kopeng__*`) are excluded. Sequence detector finds A→B tool patterns recurring across 2+ sessions within a proximity window of 4 operations
- **Synthesizer** (`src/discovery/synthesizer.ts`): Aggregates raw patterns into actionable insights. Groups repeated_tool candidates by project+tool-category (file_access, shell_infra, shell_build, browser, etc.) and generates synthesized content with workflow recommendations (e.g., "Key reference files: X, Y, Z" or "Manual infra checks — automation candidate"). **Sequence chaining (thin Skills layer):** overlapping `sequence` bigrams within a scope (A→B, B→C) chain into a single multi-step "Workflow: A → B → C" candidate tagged `synthesized_tags: ['skill','workflow']` (weakest-link evidence — min evidence_count / distinct_sessions across members); un-chained bigrams pass through. Other non-repeated_tool patterns pass through unchanged
- **Discovery engine** (`src/discovery/discovery-engine.ts`): Pipeline: detect → synthesize → confidence → security denylist → dedup → store. Watermark cursor, optimistic locking, three-tier semantic dedup (>=0.95 reinforce; 0.85-0.95 **classify-before-reinforce** since D2.2 — **a deterministic T31 referent guard runs first**: same-template + different-referent discovery pairs (sequence "A → B" bigrams, repeated_tool payloads, key-files lists) `create` without consulting the reasoner and never plant a junk contradiction flag, and numeric-only re-observations ("5 occurrences" vs "7", T28) take the Phase-1 reinforce; only pairs the guard declines reach the shared dream reasoner, where only a confident `duplicate` still reinforces+logs, a confident `unrelated` creates without reinforcing (R13 ingestion fix), supersession-shaped verdicts (`preference_change`/`conditional`/`contested`) create the new memory AND flag the pair (`contradiction-flagged` tag + `metadata.contradiction_flag` naming the partner) for the dream layer, while no-reasoner/NoOp/low-confidence keeps the Phase-1 reinforce+log; <0.85 create)
- **Confidence** (`src/discovery/confidence.ts`): Self-limiting reinforcement `+0.05*(1-current)`, ceiling at 0.85. Read-time decay (D1.1): the clock anchors on `last_seen ?? updated_at` and is scaled by durability `1 + ln(observation_count)` (`Δt_eff = Δt/durability`) — well-evidenced memories decay slower; `confidence=1.0` never decays. **Column separation:** correction (`update_memory`) touches `content`+`updated_at` only and never resets the decay clock; usage lives on `observation_count`+`last_seen`, bumped by `reinforceOnAccess` at genuine surfacing points (recall results, search results, `GET /api/memories/:id`) and by discovery re-observation — so a recalled memory resets its decay clock, an un-recalled one keeps aging. The dormant-project freeze applies in discovery-maintenance archival (not at search time). Derived strength + the storage-vs-retrieval orthogonality doc live in `src/dreaming/scoring.ts`. **Phase 4: the archive line has ONE spelling.** `isDecayedAtRisk` (`src/dreaming/scoring.ts`; threshold constant `DECAY_ARCHIVE_THRESHOLD = 0.2` exported from `confidence.ts`) is the only predicate any archiver or panel consults — promotion decay archival, the dream `decay` tier, maintenance §2, and the corpus-health `decayed_at_risk_count` all call it, guarded by the extended `isAnchored` Hard-Anchor contract (`is_locked` — THE anchor — with `metadata.pinned` / `confidence >= 1.0` as DEPRECATED spellings, still honored this release). Set-equality across all four consumers over one seeded corpus is pinned by `tests/unit/decay-predicate-composition.test.ts`, whose grep-guard fails on the drift shape Tasks 3–5 eliminated — a strength/confidence-named identifier compared `<`/`<=` against a literal `0.2` in `src/` or `scripts/` — and (team round F-B) on any non-allowlisted file that both calls `memoryStrength`/`computeEffectiveConfidence` and compares anything against a literal `0.2` in comment-stripped code (the split-identifier evasion). Honest scope: the set-equality groups lock only the four WIRED consumers; consumers outside the suite are caught by the guard's literal + co-occurrence rules; genuinely novel spellings in new files (`0.20`, `.2`, an inverted `>= 0.2` — recorded in tracker Round 24) remain a review concern. Error patterns get enhanced scoring: cross-session bonus (+0.10), fix shortcut (3 with fix → 0.65). **Type-tuned decay + crystallization + floors (T30, `docs/dreaming/t30-type-tuned-decay-plan.md`):** the single 60-day half-life is now a per-type table (`DECAY_HALF_LIVES`: error 11d, discovery 25d, project 45d, reference 38d, feedback 90d, default 60d; `resolveHalfLife(type, tags)` — a discovery memory carrying an `error*` tag is the fast class) threaded through `computeEffectiveConfidence`/`memoryStrength` and the decay call sites (`type`/`tags` added to `StrengthInputs` + `CandidateMemory`). Structural facts get a **decay floor** (`STRUCTURAL_FLOOR` 0.4 for `reference` type or a `structural`/`canonical` tag, clamped to at most stored confidence) so paths/endpoints/conventions never decay under the 0.2 archive line while still true (`resolveFloor`); floors **co-ship** with the per-type half-lives (the 38d reference curve is only safe because the floor catches its tail — Phase-0 finding). **Auto-crystallization** (`src/promotion/crystallize.ts`): a durable memory (`observation_count ≥ 10`, age ≥ 7d via `created_at` — the cheap cross-session/anti-burst proxy since `memory_access_log` carries no session id, `confidence ∈ [0.6, 0.97)`, unlocked) is promoted to **0.97** ("sticky, not a Hard Anchor" — decays slowly + floored, still consolidation-visible/supersedable, so `1.0` stays the *deliberate* operator anchor per T23) as a REVISIONED step of the promotion pass (snapshot-first → `updateConfidence`, reversible via rollback, idempotent since 0.97 ≮ 0.97; no `dream_audit_log` row — the revision snapshot IS its reversibility record), **gated OFF** by the `auto_crystallize` `operator_config.config` blob flag (GATE posture like `auto_accept_*`; `readAutoCrystallize`). The `confidence ≥ 1.0` Hard Anchor short-circuit runs FIRST, before any per-type curve / floor / crystallization, so deliberate anchors are untouched. Pure config+math, no reasoner — the LLM-out-of-write-path invariant is untouched. Corpus-validation harness: `npm run analyze:type-decay` (read-only, T30.0)
- **Scheduler** (`src/discovery/scheduler.ts`): Debounced interval timer with starvation fallback. R5: each pass acquires-or-skips the consolidation lock — a skip (nightly promotion → dream chain mid-flight) preserves the observation counter so the next tick retries
- **Maintenance** (`src/discovery/maintenance.ts`): Observation purge, low-confidence archival, cross-scope promotion. **Phase 2: both archive sites are audited, never bare.** The low-confidence sweep (§2) builds a `decay` `DreamDiffEntry` per candidate and runs it through the standard `applyEntry` path — and (team-review #22) it **honors `auto_accept_decay`** (read via `MaintenanceAuditDeps.configStore`, the same GATE-1 flag governing every automated decay archive): flag off, unreadable, or no config store wired ⇒ candidates are WITHHELD, not archived. **Phase 4 (§2):** the sweep pages the FULL active discovery set (the old 500-row single-page cap silently exempted every newer row from the sweep), selects with the shared `!isAnchored && isDecayedAtRisk` predicate, and its dormant-project freeze is **alias-group-aware**: `MaintenanceAuditDeps.expandScope` widens the canonical scope to its alias group and dormancy is judged over the group's pooled observation recency, so a client active under one alias variant is not archived under another. **R4-B (ruled 2026-08-20): dormancy is an explicit per-site input, not part of the shared predicate** — §2 keeps the D1.1 freeze; promotion, the dream decay tier, and the corpus-health panel deliberately pass no freeze (six weeks of blessed freeze-less archives), the delta pinned by `tests/unit/decay-predicate-composition.test.ts`. **Task-5 discovery (Phase 4):** `getObservationStats(scope)` ignored its scope argument in the oldest/newest-observation range on BOTH backends, so the D1.1 dormant freeze had been silently corpus-global since it shipped — fixed (scoped SQL, pinned SQLite + PG), so the freeze is now genuinely per-scope-group, matching D1.1's documented intent for the first time. **§3 scope promotion (reworked, team-review #22; hardened r2):** groups by `normalizeContent` — the SAME predicate as the dream selector's cross-scope tier (the old `content_hash` grouping was unreachable: the hash carries a GLOBAL unique index, so cross-scope rows can never share one) — and promotes by **RE-SCOPING the best original to `global`** (fresh `peek` + anchor re-check at rescope time, then snapshot-first → `update` from the FRESH row → audited `promote_global`/`rescope`, compensate-restore on audit failure; reversible via rollback since Phase-2 revisions restore `scope`), not by creating a new row (`store()`'s scope-agnostic hash dedup made create-from-best structurally impossible, and a created row had no undo path). **Gated (r2): §3 is OFF by default** — the `auto_promote_global` `operator_config.config` blob flag (`readAutoPromoteGlobal`, same GATE-1 posture/mechanism as T30.3's `auto_crystallize`) must be armed or every group is WITHHELD; §3 archives N originals AND widens content to the every-project `global` scope, so it must not be the one ungated automated archiver. The distinct-scope bar counts **canonicalized** scopes (`MaintenanceAuditDeps.canonicalizeScope` — alias variants of one client can't fake 3 scopes). Order is archives-first/rescope-last with an anchored-member pre-scan, and any mid-group failure **compensates the members archived so far** (unarchive + vector re-add + `compensate_unarchive` audit note) so the group reverts whole — "originals archived, no global" is loss of reachability, the worse failure mode, whereas a stray global dup would merely self-heal via corpus-health/dreaming. `promoted_to` is stamped only AFTER a member's successful archive. Note (r2): the survivor keeps its own confidence — the old create-path's `min(0.85, avg)` cap is gone, deliberate (it is the same row, id-stable, operator-raisable). The dream selector's own `promote_global` entries stay **diff-only/informational** (`applyEntry` returns `not_actionable` for them) — maintenance independently re-detects with the same predicate and is the path that applies. Both sites share one lazily-created **maintenance carrier dream** (`reason: MAINTENANCE_CARRIER_REASON`, `mode: 'whole_corpus'`) as the audit/rollback FK target, via the shared `CarrierDream` helper (`src/dreaming/carrier.ts` — ONE definition of the create → record → finalize lifecycle, also used by `autoArchiveDecayed`'s promotion carrier; finalize is try/catch-guarded so a summary-row failure can't 500 the route). **Carrier visibility (team-review #22):** carriers ARE listed by `listRecentDreams`/`/api/ops/dream-history` (labeled `is_carrier` — they perform real archives, so history is their operator-facing record) but stay excluded from `getLastCompletedDream` (the once-per-period scheduler gate) and `listPendingDreams` (the review queue; the exclusion now lives in the query on both backends, not in the writers' hardcoded acceptance values). Without `MaintenanceAuditDeps` (`dreamStore`/`vectorIndex`) wired, neither site bare-archives: §2 reports its candidates as `memories_withheld` and §3 skips the whole group — same WITHHOLD posture as R14 decay archival. `POST /api/admin/discovery/maintain` acquires the consolidation lock (`ConsolidationLockManager`, `uniqueHolder('discovery-maintenance')`) when a dream store is wired, 423 when busy elsewhere; falls back to an unlocked, unaudited call only when dreaming isn't configured at all. `MaintenanceResult` gained `memories_withheld` and an optional `dream_id` (the carrier's id, for `POST /api/memories/:id/rollback`) — both additive.
- **Search integration** (`src/search/hybrid.ts`): Confidence blending `score * (floor + (1-floor) * confidence)` with 70:30 result partitioning

Key design: auto-discovered memories use `type: 'discovery'`, `source: 'auto-discovery'`, confidence capped at 0.85. Operator confirms via `update_memory` to reclassify and raise confidence to 1.0.

**Procedural "Skills" track (thin Skills layer, no new `MemoryType`):** `sequence` patterns are repeatable workflows. The detector emits structured `steps` (`PatternCandidate.steps`, e.g. `['Read(routes.ts)','Bash(tsc)']`); the synthesizer chains overlapping bigrams into multi-step `steps`. `createDiscoveryMemory` marks them for legibility via `deriveSkillKeyAndName` — which builds `metadata.external_key` (`skill:<step>>...`) and `metadata.name` (the arrow chain) **verbatim from `steps`** (no re-parsing of the human `description`, and no case-folding so the key stays 1:1 with content). The `SKILL_TAG` push is **coupled to keyability** — a memory is tagged `skill` only when it's keyable, so tag ⟺ `external_key`. They stay `type: 'discovery'`, `scope: project:<name>`. Surfaced by the `/api/surface` procedural-skill lane (below) as **advisory** (auto-derived, unconfirmed), not just generic recall. `SKILL_TAG`/`CLAUDE_INDEX_TAG` are shared constants in `src/types/types.ts` (the producer↔consumer contract).


### Error Pattern Detection

The observation hook classifies tool failures by parsing output for error patterns. Detected errors are stored as `status: 'failed'` observations with `error_category` and `error_signature` in metadata.

**Error categories:** `typescript` (TS error codes), `test_failure` (vitest/jest/mocha), `runtime` (TypeError/ReferenceError/etc with stack traces), `build` (tsc/esbuild/webpack failures), `command` (ENOENT, command not found), `lint` (eslint/biome), `edit_conflict` (Edit tool failures), `import` (module not found), `permission` (EACCES), `git` (merge conflicts, fatal errors), `general` (non-zero exit codes).

**False positive guards:** Negative patterns (`0 errors`, `All checks passed`), multi-signal requirements (e.g., runtime errors need stack trace frames), only Bash output classified for most categories.

**Tiering model:** Errors progress through confidence tiers based on recurrence:
- Noted (2 occurrences, ~0.50): search only
- Pattern (3+ cross-session, ~0.60): appears in recall
- Actionable (5+ or 3 with fix, ~0.65+): proactive surfacing
- Confirmed (operator approves, 1.0): permanent knowledge

**Proactive surfacing:** On error detection, the hook writes `~/.kopeng/hints/last_error.json`. The recall hook (`memory-prompt-search.sh`) reads this hint on the next prompt, augments the recall query with error context, and surfaces matching error pattern memories. Hint files auto-expire after 5 minutes.

Error patterns are tagged with `['auto-discovered', 'recurring_error', 'error-pattern', 'error:<category>']` for searchability.
