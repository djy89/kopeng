### Dreaming Layer (`src/dreaming/`) — Phase 0, feature-flagged

Autonomous nightly memory consolidation ("the Librarian"). Gated by `DREAMING_ENABLED` (default OFF; **enabled on live since 2026-06-09** — GATE 0 passed, first PG dream pass verified completed→collapsed same day). Plan: `docs/dreaming/implementation-plan.md`; current status + amendments: the maintainer build tracker (not shipped) and `docs/dreaming/fable5-review-2026-06-09.md`.

- **Fire predicate** (`fire-predicate.ts`): pure `shouldDreamFire()` — fires only when not-run-today (operator-local day, DST-correct via Intl) AND inside quiet hours AND idle. Scheduler owns clock/stores; predicate owns logic.
- **Activity tracker** (`activity-tracker.ts`): Fastify `onRequest` hook stamps operator activity; `isActivityPath` excludes health/ops/dreams/SSE — and slot READS (`GET /api/slots*`, polled by the viz slots tab; slot writes still count) — so background polling can't reset the idle clock (R8). When observation ingestion is on, the scheduler floors the idle signal with `MAX(observations.started_at)` (`IObservationStore.getLastObservationAt`) — in-process stamp OR observation recency, whichever is newer — so a service restart can't fake idleness (R3). Ingestion off → tracker-only.
- **Scheduler** (`scheduler.ts`): interval tick → predicate → injected `runDream` action; `triggerNow()` bypasses the predicate. Reads tz/idle/quiet from `operator_config` (DB) with `config.dreaming` fallbacks. **Hot kill-switch:** `operator_config.dream_cadence = 'off'` stops every SCHEDULED fire before the predicate runs (`cadence_off`) — no restart, covers nightly windowed and whole-corpus schedulers alike; manual triggers bypass `evaluate()` and keep working. Any other value (null/`'nightly'`) is the default firing behavior. Togglable from the viz review tab's dreaming-controls panel (PATCH `/api/operator-config`). **T6.3 (round 2): the monthly whole-corpus sweep is WIRED** — same tick, evaluated only when the nightly pass doesn't fire (one scheduled fire per tick); composed gates cheapest-first: kill-switch → blob cadence (`dream_whole_corpus_cadence`, shipped default `off`; the review-tab toggle arms `monthly`) → once-per-period over COMPLETED whole-corpus dreams → the same quiet/idle window as nightly. Fires `runDream(trigger, reason, 'whole_corpus')`; the engine acquires its own lock (acquire-or-skip — a busy nightly chain just defers the sweep to a later tick). Last-run day comes from `getLastCompletedDream(operator, scope, mode)` — completed-only, per-key — so a failed dream doesn't claim the day and a dream in one scope doesn't starve another (R2). **T9:** the two per-tick PG reads (`getLastCompletedDream`, `getLastObservationAt`) go through `readWithRetry` — a transient pooled-connection drop ("Connection terminated due to connection timeout") retries once then degrades to a single `warn` (never an error-per-tick), and the pool (`postgres.ts`) raises `idleTimeoutMillis` past the tick interval + enables TCP `keepAlive` so idle connections aren't reaped between ticks.
- **Engine** (`dream-engine.ts`): `runDreamPass` — pipeline run + `dreams` row written **inside the consolidation lock**; idempotent per `window_key`: non-failed dreams collapse the window, failed dreams are retried on later ticks (bounded, `MAX_WINDOW_RETRIES = 2`; the partial unique index excludes `status='failed'` so retry inserts land); dry-run writes nothing; `skipped` when the lock is held elsewhere. Manual trigger: `POST /api/dreams/trigger` + `trigger_dream` MCP tool, both accepting an optional `window_key` override to re-run after the daily window collapsed. **D1.3 auto-apply step:** after the diff is stored (still inside the lock hold), deterministic-safe entries whose operator flag is ON apply via `apply.ts`; everything else queues. Per-entry apply failures leave that entry pending — the dream still completes. **D2.2:** live windows are wrapped with `withFlaggedPairs` (same file) — every fetch is augmented with ingestion-flagged contradiction pairs + their partners (bounded, 50/pass) regardless of rotation position, and after the diff is stored the engine consumes the routed pairs' flags (`consumeContradictionFlags` — tag + metadata stripped so the pair never re-queues; the queued entry is the baton). **Baton-drop fix (found Phase 6, CLOSED pre-T17):** consumption reads `PipelineResult.classifiedCandidates` — only the groups the pass actually classified — not the full selector candidate list, so a flagged pair the T6 whole-corpus `reasonerGate` drops (out-of-segment) keeps its flag and re-queues when its segment arrives, instead of losing the flag with no queued entry (the drop was reachable via the manual `POST /api/dreams/trigger {"mode":"whole_corpus"}` regardless of the cadence flag — the gate installs by SOURCE type). Pinned by the gated-out-then-consumed round-trip in `tests/unit/dream-whole-corpus.test.ts`. The criterion is classified-not-entry-producing, deliberately: a consumable `unrelated` verdict on a flagged pair produces no entry yet must still retire the stale flag.
- **Apply path** (`apply.ts`, D1.3): the code that performs a dream's memory mutations. Every write that CHANGES an existing memory is snapshot-first and audited: snapshot to `memory_revisions` → archive the live row → append `dream_audit_log` (audit-append failure compensates by unarchiving — no unaudited change survives, invariant #11); the vector index drops archived ids. **T76 (T-M5):** `change_class` is now two types, not one — `DreamDiffClass` (the review-pipeline proposal) and `DreamAuditClass` (the applied-change record), sharing only the members that genuinely appear in both; `rollback` and the new `archive_ephemeral` are audit-only (never proposed as a diff), `contested` is diff-only (queued for the operator, never applied, hence never audited), and Phase B's `curation` is reserved on the diff side only. `dream_audit_log`'s own `change_class` CHECK gained `archive_ephemeral` (SQLite v13 child-table rebuild / PG v15 constraint swap — `'decay'` would have been false audit data for a scope-level archive), enforcing the split at the database, not just the type system. **The snapshot→archive→audit→compensate core is `auditedArchiveMemory()` (Phase 2)** — the audited-archive primitive for every automated CONTENT-MUTATING archive, extracted out of `applyEntry`'s archive loop: re-checks missing/anchored/already-archived per call so retries stay idempotent, returns `'archived' | 'skipped_missing' | 'skipped_archived' | 'refused_anchored'`. Discovery-maintenance (below) is the other caller. Bounded exception (ruling 4, team-review #22 A8): `rollbackDreamCreation` archives directly with a best-effort audit — compensating there would un-do the rollback the operator just asked for. **Member reads are non-reinforcing (team-review #22 P2; completed r2):** `applyEntry` builds one per-invocation member cache over `IMemoryStore.peek()` (the read that skips the access log; `get()` is a surfacing point) shared by the three revalidation steps and the archive loop — one quiet read per member per apply, and a refused-stale entry no longer plants access-log rows for a proposal that applied nothing. The doctrine covers the WHOLE apply path (r2): `applySupersession`, `applyConditionalEncode`, `rollbackDreamCreation`, and the `GET /api/dreams/:id/diff` member excerpts all read via `peek()`; the one deliberate `get()` is `rollbackMemory`'s (a rollback is a rescue — it reinforces on purpose). **Two bounded exceptions to the snapshot+audit shape:** a memory the pass CREATES (a `conditional` branch encoding) is audited on creation but has no prior state to snapshot (undone by archival via rollback, B5); and `consumeContradictionFlags` strips a consumed routing flag's tag/metadata OUTSIDE this path — idempotent bookkeeping, not a content change, and a lost flag merely re-queues the pair. Auto-apply gating is strictly flag-per-class: `exact_dup` ⇐ `auto_accept_exact_dup`, `decay` ⇐ `auto_accept_decay` (both ship OFF — GATE 1 governs the flip); deterministic-safe `merge` (cosine ≥0.95) and `promote_global` (diff-only signal) ALWAYS queue, as do reasoner-driven entries. Per-entry `resolution` (`auto_applied`/`accepted`/`rejected`) persists in `output_diff`; dream acceptance derives from it (`computeAcceptance` — `partial` = some pending or mixed accept/reject). Hard Anchor is re-checked at apply time via the shared `isAnchored` contract — `metadata.pinned` included since Phase 4, when `apply.ts`'s private `isAnchoredRow` was folded into the one predicate (stale-diff defense; `tests/unit/anchor-contract.test.ts`). **Phase 2 apply-time revalidation** (`applyEntry`, before the archive loop — a stale-diff defense for diffs that may have sat pending across other mutations): (1) **keep-target liveness (G3)** — if the proposal's `keep_id` is missing or already archived, the whole entry is refused `not_actionable` (`stale diff: keep target …`) and NOTHING is archived, rather than collapsing members toward a dead survivor; (2) **provenance hash check** — when the entry carries Task 4's `provenance.members` (absent on pre-Phase-2 diffs, which skip straight to the keep-target check), a live `content_hash` mismatch against the stamped hash also refuses the entry (`stale diff: … content changed`); (3) **canonical-survivor preference**, `exact_dup` only — if `keepMem`'s scope canonicalizes (via `deps.canonicalizeScope`) to a DIFFERENT scope and one of the proposed archive-members already sits on that canonical scope, the proposal swaps keep/archive so the already-canonical row survives. The closure is wired on BOTH consumers (r2 NEW-1): the operator-resolve path (routes.ts `applyDeps`) AND the engine's auto-apply path (`DreamEngineDeps.apply.canonicalizeScope`, wired in server.ts) — it was originally resolve-only, leaving the preference inert on the one unattended path where `exact_dup` can auto-apply. The swap is gated on `normalizeContent(keepMem.content) === normalizeContent(candidate.content)` — the SAME predicate the selector used to form the `exact_dup` group — not raw `content_hash` equality: `content_hash` is globally unique, so two live rows can never share one, which would make a hash-equality gate dead code. The swap's entry mutation is **persisted unconditionally** by the engine (team-review #22 A1 — the old `autoApplied > 0` gate discarded a swap followed by an anchored refusal, leaving a stored diff that named the archived row as survivor; regression pinned in `tests/unit/dream-apply.test.ts`), and the rationale marker is append-once so retries don't stack it. **D2.2 executors (operator-accept only — reasoner-driven, so auto-apply can never reach them):** `supersede` sets `deprecated_at` on the old row and `valid_from` (= its created_at) on the new, BOTH stay active (chain, not archive; audited as `supersede` deprecate/mark_current; compensated on audit failure; rollback restores the markers — snapshotted since SQLite v7 / PG v9); `conditional` creates the branch-encoding memory via the injected `embedText` ({vector, model}; absent → entry stays pending) with `condition_sources` provenance, then snapshots each original and applies `markContradicted` (last_contradicted + observation_count→1, durability reset); `contested` is review-only — accept returns not_actionable (operator acts via update/archive_memory, then rejects the entry). **Review surface:** `GET /api/dreams/pending`, `GET /api/dreams/:id/diff` (human-readable: rationale, evidence counts, confidence deltas, member excerpts — member reads deliberately not reinforcement points), `POST /api/dreams/:id/resolve` `{action: accept|reject, entry_indices?}` (partial = subset of indices; accept runs under the consolidation lock, 423 when busy; reject touches only the dream row). **Rollback:** `POST /api/memories/:id/rollback` `{revision?}` + `GET /api/memories/:id/revisions` — restores content + embedding + tags + (Phase 2) scope/type/last_seen + (WS0) the `is_locked` Hard Anchor from the snapshot (the store snapshots the pre-rollback state first, so rollback is itself reversible), unarchives, re-syncs the vector index, audited BEST-EFFORT as change_class `rollback` (the append is `.catch`-logged after the restore lands, so a failed audit write leaves the rollback in place — unlike the apply path, which compensates); a dream-CREATED memory with no revision is instead archived (audited `rollback`/`archive_creation`), so every dream write has an undo path (B5). **Phase 2 rescue semantics (G1):** after restore + unarchive, `rollbackMemory` calls `dreamStore.reinforceMemory(memoryId)` — bumping `last_seen` and `observation_count` — because a rollback is the strongest access signal ("a recall rescues a memory from archival" doctrine, amplified): merely restoring a decay archive's ancient snapshotted clock would let the next promotion pass re-archive it within ~24h. Not applied to `rollbackDreamCreation` (that path archives, it does not rescue). **Rollback audit stays dream-linked-only (ruling 4):** a rollback of a revision with `created_by_dream_id = NULL` — the new every-mutation PUT snapshots (below) and T30.3 crystallization — appends no `dream_audit_log` row; the `restoreRevision` pre-rollback snapshot IS its reversibility record, same posture as crystallization. D1.3/Phase-2 apply actions never change content, so no re-embed is needed and Neo4j stays read-only (invariant #7).
- **Crystallization audit path** (`src/promotion/crystallize.ts`, T43): auto-crystallization (promoting a durable memory's confidence to `CRYSTALLIZE_TARGET` after enough reinforcement) is now audited, not snapshot-only. Every promotion in a pass opens a lazy carrier dream (`CRYSTALLIZE_CARRIER_REASON = 'auto-crystallization (T43 audited path)'` — a run that finds nothing eligible writes no dream row) and applies the same invariant-#2 discipline as the rest of this file: snapshot the pre-crystallize confidence to `memory_revisions`, call `updateConfidence`, then `appendAudit` with `change_class: 'crystallize'`; a failed audit append compensates by restoring the prior confidence rather than leaving an unaudited mutation standing. `dream_audit_log`'s `change_class` CHECK gained `crystallize` (SQLite migration v15, table rebuild via the v13 mechanism; PG migration v17, constraint swap) alongside the existing classes. Without a dream store to audit against, a live pass WITHHOLDS rather than crystallizing unaudited — same posture as every other archiver in this file. Dormant while `auto_crystallize` (`operator_config.config`) is OFF; the confidence bump changes no content, so no re-embed and Neo4j stays read-only (invariant #7), and every crystallization is rollback-able via `POST /api/memories/:id/rollback` like any other snapshot-first change.
- **Pipeline** (`pipeline.ts`): `MemorySource → CandidateSelector → Reasoner → DiffGenerator`. D1.2 ships real detection: `DuplicateCandidateSelector` tiers — same-scope union-find over exact-normalized-content ∪ cosine ≥0.95 edges (collapse tier, `exact_dup`/`merge`, deterministic-safe), the 0.85–0.95 near-dup band (pairs only, `merge` tagged **reasoner-driven**, never collapsed — may hide a contradiction), cross-scope same-content dups (R6 → `promote_global` signal for the maintenance promotion path, never a collapse), and durability-aware decay singletons (the shared `isDecayedAtRisk` archive-line predicate since Phase 4 → `decay` archive proposal). **Phase 2 alias-aware grouping:** the selector accepts an optional `canonicalize?: (scope: string) => string` closure — every member-scope comparison that decides same-scope-vs-cross-scope (the same-scope bucket key, the cross-scope distinct-scope set, `classifyDupPair`'s `sameScope` check) routes through it when present, so two alias variants of one client (`client:Acme-Foods` / `client:acme-foods`) group as a same-scope `exact_dup` instead of impersonating a cross-scope `promote_global` signal. No closure ⇒ identity ⇒ byte-identical to pre-Phase-2 grouping (the replay harness wires no resolution snapshot, so its proposals are unchanged). `classifyDupPair` is also called by the `/api/ops/corpus-health` dup scan, which passes the SAME alias closure (one `readScopeResolution()` per compute, fail-open to identity — team-review #22): without it an alias-variant pair the selector collapses would read `cross_scope`/"by-design exempt" and `actionable` would report 0 during exactly the state it exists to expose (agreement pinned by `tests/unit/pipeline-alias-scope.test.ts`). **P1 (team-review #22):** `select()` is now async — per-bucket normalized content is hoisted out of the O(n²) pair loop (~8x) and the scan yields to the event loop every 16 outer rows (the corpus-health convention), so a whole-corpus pass can't starve the recall hook's 3s budget. `DeterministicDiffGenerator` emits the tagged `DreamDiff` with machine-actionable `after` proposals (keep/archive ids) that the D1.3 apply path executes. **Phase 2 diff provenance:** the generator takes `{ aliasVersion?, canonicalize? }` and stamps every entry (including router-produced `near_duplicate`/`flagged` entries) with `DreamDiffEntry.provenance = { alias_table_version, members: [{ id, content_hash, scope, effective_scope }] }` — the apply-time revalidation inputs (see Apply path, above). Absent `provenance` (legacy pending diffs, or no resolution snapshot wired) means the hash check and canonical-survivor preference skip; the keep-target liveness check (G3) applies regardless. `src/server.ts` takes one `scopeAliases.snapshot()` per dream pass (fail-open to `null`/identity on snapshot failure) and threads the same `canonicalize` closure + `resolution.version` into both the selector and the diff generator, so a pass's grouping and its stamped provenance always agree on which table version was in effect (one closure by construction; stamped provenance on a real composed-server dream is pinned by probe 3 of `tests/integration/server-wiring.test.ts`). Evidence gates (`gates.ts`: ≥3 distinct sessions, ≥2 distinct inputs, ≥24h span over `evidence_snapshot`) demote unevidenced semantic merges to reasoner-driven; exact dups bypass the gates. `runPipeline` is LLM-last: classification covers band pairs, ingestion-flagged pairs (`flagged_contradiction` — a selector tier claimed FIRST, emitted only when both sides are present and unanchored), gate-DEMOTED semantic pairs, and legacy signal-less pairs; gate-passing deterministic signals never see the LLM. A consumable `conditional` verdict additionally triggers `extractCondition` (also raced against the pass budget). **D2.2 selector guards:** band pairs touching a `deprecated_at` memory, pairs where both members carry `last_contradicted`, and condition-provenance links (`metadata.condition_sources` — an encoded memory is similar to its sources by construction) are never re-proposed. Hard Anchor: the shared `isAnchored` contract (`is_locked` — THE anchor — with `metadata.pinned` / `confidence >= 1.0` as DEPRECATED spellings, still honored this release; Phase 4 extended it to the pin; `tests/unit/anchor-contract.test.ts`) bypasses members (real `is_locked` + `metadata` surfaced by the window sources via the shared `toCandidate` mapping — verified live, else the selector-level pin exclusion would be inert). **D1.4 rotating window:** live passes use `RotatingWindowMemorySource` (dream-engine.ts), not newest-500-by-id — each pass takes the next `limit` active ids ascending after a persisted cursor (`operator_config.config` → `dream_window_cursor`, keyed by scope), wrap-filling from the bottom at the top of the id space, so the whole corpus is revisited every ceil(N/limit) passes (backed by `IMemoryStore.listByIdRange`, both backends). The cursor advances ONLY on dream completion (failed pass retries the same segment; dry-run never commits), and the `window_key` encodes it (`<day>#a<cursor>`) so R2 collapse is per-segment — a same-day manual re-trigger after completion walks the NEXT segment, while the scheduler's daily gate keys on `started_at` and is unaffected. Rotation's known limit (GATE 1, R12): far-apart MID-CORPUS pairs (restatements months apart, Δ≈2000 ids on live) are invisible to rotation's contiguous windows — the one exception is a pair straddling the wrap seam, which the wrap-fill window CAN co-window — so **delivered T6/R12 whole-corpus mode is the complete answer** (see below). Phase-0 scaffold (`WindowedCandidateSelector` + `EmptyDiffGenerator`) is kept for the replay baseline. **T6/R12 whole-corpus mode (`mode: 'whole_corpus'` — scheduled monthly sweep WIRED since round 2 but cadence ships `off`, so nothing fires until the review-tab toggle arms it; controlled first pass is operator step T17):** `WholeCorpusMemorySource` (dream-engine.ts) `fetch()`es the WHOLE active corpus for the scope (paging `listByIdRange`, both backends — no new store method, no migration; `dreams.mode` CHECK already allows `whole_corpus`) so the cheap **deterministic tier (exact_dup/decay) runs over everything every pass** — the Δ≈2000 far-apart dup that rotation can't co-window surfaces here. The slow **reasoner tier is throttled by a persisted id-segment cursor**: a band/flagged/gate-demoted pair is classified (and emitted) ONLY when its anchor `min(a.id,b.id)` falls in `[cursor, cursor+segment)` — `runPipeline`'s optional `reasonerGate` drops out-of-segment pairs WHOLE (no classify call, no Phase-1 fallback entry), so one pass emits at most a segment's worth of review-bound entries and the budget/queue stay human-sized. Cursor lives in `operator_config.config` → `dream_whole_corpus_cursor` (per scope), segment dial `dream_whole_corpus_segment` (default 60, hot-editable); the cursor advances by `segment` ONLY on completion (failed/dry-run re-cover the same segment), wrap-filling from the bottom once it passes the max active id — so successive same-week passes drain DISJOINT segments over ⌈N/segment⌉ passes. `window_key` = `<isoWeek>#whole#a<cursor>` (R2 collapse per-week-per-segment). A `>10k`-eligible-per-scope backstop logs a shard warning (the pairwise selector is reused UNCHANGED — seconds at current scale). Cadence is config-driven (`dream_whole_corpus_cadence`: `off`/`monthly`, **default `off`** — pure predicate `shouldWholeCorpusFire`, drain-then-maintenance per T6 plan); `auto_accept_*` untouched. The `RotatingWindowMemorySource` path is unchanged (no `reasonerGate` ⇒ no gating). `promote_global` stays diff-only (the maintenance promotion path applies it, never the dream apply path); the `dream_audit_log` CHECK covers `promote_global` + `rollback` since SQLite v6 / PG v8 and `conditional` since SQLite v7 / PG v9 (`contested` is deliberately NOT in the CHECK — diff-only, never audited).
- **Reasoner** (`reasoner/`): provider-agnostic `ConsolidationReasoner` interface (classify/extract/synthesize — never writes); the deterministic engine owns the write path. **D2.1 (`local-reasoner.ts`):** `LocalOllamaReasoner` — classify-only HTTP adapter to local Ollama, gated by `DREAM_REASONER_ENABLED` (env-only, default OFF; OFF or provider-down ⇒ `NoOpReasoner`-identical Phase-1 behavior). The locked classify-pair contract lives in `reasoner/prompts.ts` (JSON `{relation, confidence, rationale}` mapping 1:1 onto `PairVerdict`; grammar-constrained via Ollama's `format` param AND Zod re-validated server-side; the system prompt carries the R13 guard — template-shaped memories naming different files/commands ⇒ `unrelated`, never `duplicate`). Default model `qwen3:8b` (locked by prototype evals 2026-06-12: 40/40 incl. the real R13 live pair, 0 forbidden verdicts, ~1.9s/call on a 12GB-VRAM consumer GPU; qwen3:4b rejected — over-applied the template rule). Bounds: retry-once-then-fallback (`unrelated`/conf 0 — a downstream no-op), per-call timeout `min(settings, ctx)` via AbortController chained to `ctx.signal`, `num_predict ≤ min(maxTokens, ctx.tokenBudget)`, 1200-char content excerpts (invariant #9), `yieldToEventLoop()` before each call — all adapter-side HONOR; R4b enforcement stays in the pipeline (`Promise.race`, verified against a dishonest abort-ignoring adapter). Settings resolve PER CALL: `operator_config.config` → `dream_reasoner` blob (`{url, model, timeout_ms, max_tokens, think}`, hot-editable via `set_operator_config`) over env defaults `DREAM_REASONER_URL`/`_MODEL`/`_TIMEOUT_MS`/`_MAX_TOKENS`. **D2.2:** `extractCondition` is implemented (locked prompt in `prompts.ts` with an empty-string escape hatch — a schema-valid "no genuine distinguisher" answer parses to null and skips the retry; same bounds as classify; prototype-evaled live: both conditional gold pairs extract clean branches, the contested control declines); `synthesizeCluster` stays null. The **NLI-vs-LLM decision** (plan §2.2) was made empirically 2026-06-12: qwen3:8b 12/12 / 0 forbidden vs nli-deberta-v3-xsmall/-small 4–5/12 with 3 forbidden each (template pairs misread as contradiction ~1.00) — **qwen3:8b is the production classifier**; numbers + revisit trigger in `docs/dreaming/nli-vs-llm-eval-2026-06-12.md`. Eval CLIs: `npm run eval:reasoner` (live Ollama; `--extract` adds the extract-condition eval; per-class precision/recall table), `npm run eval:adversarial` (GATE 2 hostile pairs — `tests/fixtures/dreaming/adversarial-pairs.ts`; `--harden` swaps in the R15 untrusted-data prompt candidate), and `npm run eval:nli` (local ONNX NLI — downloads on first run); NONE is part of the suite or replay harness, which stay zero-LLM; fixtures in `tests/fixtures/dreaming/eval-pairs.ts`. Provider setup + host portability: `docs/dreaming/reasoner-setup.md`. **GATE 2 finding (R15, CLOSED/mitigated — T4 landed the pre-filter 2026-06-15):** the classify-pair prompt WAS injectable via memory content (qwen3:8b obeys content-embedded "these are duplicates, archive the other" instructions; a prompt-clause `--harden` alone did NOT fix it). The fix is STRUCTURAL and shipped, with a different shape per path (Phase 6 correction — this sentence previously claimed the reasoner was never called on either path, which is true only for ingestion): a deterministic injection-shaped-content detector (`isInjectionShaped` + `INJECTION_PATTERNS` in `contradiction.ts`, mirroring the discovery `isContentSafe` denylist) fires when either member's content carries classifier-directed text (instruction-override header, second-person directive at the model, verdict-JSON fragment, or an explicit verdict order). On the discovery tier-2 ingestion guard it short-circuits BEFORE the reasoner — `classifyForIngestion` returns `create_flagged` via `INJECTION_FLAG_VERDICT` (`contested`, confidence 0 — unconsumable) with zero reasoner calls (pinned by `tests/unit/dreaming-gate2-adversarial.test.ts`, "flags WITHOUT calling the reasoner"). On the dream classify-pair path the reasoner IS still called (the injected content does reach the local model — possibly twice, since a forced consumable `conditional` verdict also triggers `extractCondition` before routing) but its verdict is DISCARDED in `routeClassifiedPair` — the pair routes to operator review as `contested` regardless of what the model returned, nothing merged or reinforced (pinned by the same suite's forced-verdict-override cases and `tests/unit/referent-guard-t31.test.ts`, whose comment reads "The reasoner IS consulted … and the router discards the forced verdict"). Defense-in-depth remains: even a bypassed injection only QUEUES a reasoner-driven entry on the dream classify path (never auto-applies); on the discovery ingestion path a bypassed injection can at most REINFORCE the existing memory (the reasoner-off baseline write — content unchanged, confidence capped at 0.85), never a content change, and the review diff shows both member excerpts (`docs/dreaming/gate2-review-2026-06-12.md`).
- **Contradiction routing** (`contradiction.ts`, D2.2): the verdict consumer — the ONLY place a classify-pair verdict turns into a proposal. A verdict is consumed only at confidence ≥ `MIN_VERDICT_CONFIDENCE` (0.6) AND with a cited rationale (≥10 chars) — the NoOp/fallback verdict (conf 0) never qualifies, so reasoner-off is byte-for-byte Phase-1. Routing: `duplicate`→`merge` with a machine-actionable keep/archive proposal; `preference_change`→`supersede` (direction is DETERMINISTIC — newer by created_at then updated_at; a full timestamp tie is "no clear distinguisher" → `contested`, never auto-pick); `conditional`→branch encoding "when X→A; when Y→B" (extraction null → `contested` rather than fabricating); `contested`→queued review entry; `unrelated`→no entry (suppresses the R13 junk band merges; on a flagged pair it also retires a stale flag). Fallbacks without a consumable verdict: band pair → the Phase-1 queued merge verbatim; flagged pair → `contested`. **Every emitted entry is tier `reasoner-driven` → always queued as pending; nothing here can auto-apply** (verified with all auto_accept_* flags ON).
