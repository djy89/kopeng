# Scope Identity: markers, derivation, aliases, registry

> Extracted verbatim from CLAUDE.md (2026-09-07). Covers how a scope string is chosen, normalized, and ruled on.

### Anchor-Marker Scopes (P4)

The default project scope (see Scope Derivation below) is still only a guess at what a directory is *about* — a client's work lives under many differently-named folders, and an app worktree and its vault folder share a client but not a repo. A **`.kopeng.json` anchor marker** lets a directory declare its scopes explicitly:

```json
{ "scopes": ["client:acme", "project:fuel-dashboard"] }
```

`readAnchorScopes()` in `memory-prompt-search.mjs` (exported, unit-tested) walks UP from the payload's `cwd`, parses every marker it finds, and returns the declared scopes nearest-first, deduped. The hook merges them onto the base pair — `[<derived project scope>, 'global', ...declared]` — so markers are **purely additive**: with no marker anywhere on the walk, the scope list is exactly the base pair (pinned by `tests/unit/anchor-scope-marker.test.ts`; byte-identity of the rest of the request follows by construction — the marker path touches only scopes). Only the main recall call is affected; the tool-recall scope and `/api/surface` are untouched.

**Fail-open like every other guard in this file:** an unreadable, malformed, or wrong-shaped marker is skipped and the walk CONTINUES, so one broken child marker can never hide a valid parent one. Bounded on three axes (`ANCHOR_MAX_DEPTH` 12 levels, `ANCHOR_MAX_SCOPES` 16 scopes, `ANCHOR_MAX_SCOPE_LEN` 128 chars per entry, the server sanitizer's bound — team-round F-A) and resolved BEFORE the 3s `AbortSignal` is armed, so the sync reads never eat the recall budget. Format chosen by the P4 survey (a JSON file, not a fenced block in `CLAUDE.md`/`AGENTS.md`, so the scope database is machine-readable and independent of prose). Tests: `tests/unit/anchor-scope-marker.test.ts` (walk, fail-open, bounds, plus the real hook against a body-capturing stub server).

**`project` override key (RULING-C, WS7.6):** a DIFFERENT, independent key on the same `.kopeng.json` file lets a directory override its OWN default project scope (as opposed to `scopes`, which ADDS extra scopes on top): `{ "project": "project:fuel-dashboard" }` or `{ "project": "client:acme" }`. See Scope Derivation below for precedence and shape rules. The two keys are read by separate code paths (`readAnchorScopes()` above vs `deriveProjectScope()` below) and never interact.


### Scope Derivation (RULING-C, WS7.6)

`scripts/hooks/project-scope.mjs` — `deriveProjectScope(cwd)` — replaces the weak `project:<basename(cwd)>` guess with `project:<owner>-<repo>` parsed from the nearest `.git` remote, so two repos named `api` under different owners land in different scopes and two worktrees of one repo land in the same scope. Pure fs, **no `child_process`** (the observe hook runs on every tool call, and git-the-binary may be entirely absent — T57 taught us installs can be gitless). Precedence, each step fail-open (any fs/parse surprise falls through to the next step):

1. **`.kopeng.json` `project` field** (see above) — scope-shaped (`project:`/`client:` prefix, non-empty remainder, ≤128 chars) wins outright, even over a real remote in the same directory.
2. **The nearest `.git`'s remote** — walks up (same 12-level bound as the anchor walk) for a `.git` directory or a worktree/submodule `.git` FILE (resolved via its `gitdir:` pointer, and `commondir` when present, to the shared repo's config — the same mechanism `wire-client.ts`'s `linkedWorktreeInfo` uses for a different purpose). Reads `[remote "origin"]`'s `url`, else the first `[remote "…"]` found, via a line-based INI scan — no git binary invoked. Normalizes scp-like ssh, `ssh://`, and `http(s)://` forms (deep GitLab-group paths use the last two path segments) to `project:<owner>-<repo>`, spelling preserved, non-`[A-Za-z0-9._-]` characters replaced with `-`. `file://` URLs and bare local paths carry no hosted identity and fall through.
3. **`project:<basename(cwd)>`** — the byte-identical pre-RULING-C fallback, used when there's no marker override and no usable remote.

Six call sites switched from the old bare `basename(cwd)` derivation: `memory-prompt-search.mjs`, `kopeng-observe.js` (also feeds the sequence-cache filename — a derived-name change just means one cold cache per project, self-healing via TTL), `memory-session-start.mjs` + `memory-session-end.mjs` (the bare name, consistently, or session breadcrumbs orphan), `canonical-path-guard.mjs`, and `doctor.ts`'s recall probe. The server needs no awareness of this — a remote-derived scope arrives at the same write/mint choke point as any other scope string (`tests/integration/scope-minting.test.ts`). Migration runbook for existing corpora: `docs/ops/scope-derivation-migration.md`. Tests: `tests/unit/project-scope-derivation.test.ts`.


### Scope-Alias Layer (T46)

P4 markers stop *new* fragmentation at the filesystem edge; T46 addresses the accumulated stock plus the free-text write path that keeps producing casing/naming variants (`client:Acme-Foods`, `client:acme-foods`) nothing normalizes. The table is operator-curated and **never a tracked file** (the real table names clients and the repo is public) — it lives in the `operator_config` `config` blob under `scope_aliases` (`{ alias: canonical }`), edited via the admin-gated `PATCH /api/operator-config`. **Whole-map replace semantics:** the T26 blob merge is per top-level key, and `scope_aliases` is one key — a PATCH must resend the FULL map, there is no per-entry patch.

`ScopeAliasService` (`src/services/scope-alias.ts`) lazy-loads the table with a 60s TTL cache; `invalidate()` drops it immediately and is wired into the operator-config PATCH handler so an edit is live on the next write/recall instead of waiting out the TTL. Validation is **fail-open and exact-match only**: `buildAliasMaps` skips non-string mappings, self-maps, and any entry whose alias key is itself a canonical value elsewhere (chains are forbidden — no string can be both an alias and a canonical), warning per skip; a missing or corrupt table degrades to identity mapping and never blocks a write or recall (pinned by `tests/unit/scope-alias.test.ts`).

Three layers:

- **Write-time canonicalization.** A `canonicalizeScope()` helper in `src/api/routes.ts` resolves the incoming scope through the service (identity when no service is wired) at all five write sites: `POST /api/memories`, `POST /api/memories/batch`, `PUT /api/memories/:id` (only when the patch supplies a scope), `POST /api/slots`, `PUT /api/slots/:slot_key`. Discovery gets the same treatment via an optional `canonicalizeScope` threaded through the `DiscoveryScheduler` constructor into `DiscoveryEngineOptions`: the canonical scope drives dedup search and the created memory's scope, while the raw `project_scope` stays on candidates and `discovery_runs` so observation lineage is untouched. Absent everywhere ⇒ byte-identical to pre-T46.
- **Read-time expansion: recall + search + surface, plus opt-in list (Phase 4 widened it from recall-only).** `POST /api/memories/recall` expands each requested scope to its alias group (`scopeAliases.expand()` — the canonical, every alias of that canonical, and the scope itself, deduped, request order preserved) so un-migrated rows (still on an alias) and migrated rows (on the canonical) are both reachable during the transition. The documented single-scope→global fallback branches on the CALLER's original scope count, not the post-expansion count, so a single aliased scope with zero hits still falls back to `global` rather than silently returning empty. **Phase 4:** `POST /api/memories/search` gets the same expansion (recall parity, `tests/unit/search-alias-expansion.test.ts`; MCP `search_memories` inherits), and `POST /api/surface` resolves canonical + alias group + declared anchor scopes server-side (probe 7, `tests/integration/server-wiring.test.ts`). `GET /api/memories` listing still does **not** expand by default — exact scope match, deliberate: the migration driver's residual check depends on an exact match to prove a scope is empty post-migration — with the opt-in `expand=aliases` query param for consumers that want the merged alias-group view (refused alongside `cursor` with a 400).
- **The two operator scripts.** `npm run propose:scope-aliases` (`scripts/ops/propose-scope-aliases.ts`) is read-only: it clusters the live scope inventory (`GET /api/stats`) into mechanical merges, cross-prefix judgment calls, ephemeral-scope archive candidates, and near-miss pairs, then writes `~/.kopeng/reports/t46-alias-draft.{json,md}` for operator review — nothing is written to the server. `npm run migrate:scope-aliases` (`scripts/ops/migrate-scope-aliases.ts`) is the audited bulk re-scope driver: table from `GET /api/operator-config` or `--file`, dry-run by default, `--apply` to write, `--only <scope>` to restrict, one audited `PUT /api/memories/:id` per row (never direct SQL), a residual check, non-zero exit on any failure or residual. Copy-first discipline: run the migration against a copy of the server before ever pointing `--apply` at live.

Synthetic example only (the real table is never in a tracked file): `{"client:Acme-Foods": "client:acme-foods"}`.


### Shared Scope Definition (Phase 1)

The alias-table semantics used to be implemented four times and disagree: `ScopeAliasService` rejected self-maps and chains, the drift endpoint's own reader accepted every `{string: string}`, and the migration driver checked only string-ness. The failure that forced the fix: a **chained** entry is ignored by the exact-match write path (new rows keep landing on the alias scope) while the drift detector saw `aliased_to` non-null, called the cluster covered, and reported `active_rows_adrift: 0` — a watchdog reading clean during the exact failure it exists to detect.

`src/scopes/resolver.ts` is now the single definition. `buildScopeResolution(raw)` is pure (no I/O, no clock) and returns `{ version, forward, groups, rejected, table }`: the accepted maps, a content hash of the accepted table (key-order stable; rejected entries excluded), and every skipped entry with a reason — `non_string` | `empty` | `self_map` | `chained` | `generic_capture` | `malformed_scope`. `slugifyScope` also lives here now (re-exported by `drift.ts`), because the validator and the detector both need the fold and two copies of it would be this phase's own bug.

Two rejection classes are new. **`malformed_scope`**: both sides must be `global` / `project:*` / `client:*` — three deployed P6 markers carried `status:archived`, which is not a scope. **`generic_capture`** (P13): reject iff the key is `project:<generic-name>` AND the value's bare name differs — an auto-minted generic key routed into a *different* namespace. `project:web → client:<x>` and `project:src → project:kopeng` are rejected; `project:Web → project:web` (pure fold, captures nothing) and any `client:*` key (operator-authored, never minted from `basename(cwd)`) are allowed. Generic project names remain perfectly legal as scopes — the rule constrains alias-table entries only. Note the inverted formulation that looks right and is not: rejecting generic keys only when no client scope is present would have **permitted all four entries that caused P13**, since every one of them pointed at the same `client:*` scope. The client on the right is what made them harmful, because it is what turned "a folder called web" into "that client's work, forever, for every client".

Every consumer reads that one accepted map. `ScopeAliasService` is now a **caching wrapper only** — it owns the 60s TTL, the logging and the fail-open policy, and no semantics — exposing `snapshot(): Promise<ScopeResolution>` beside `canonicalize`/`expand`/`invalidate`; `buildAliasMaps` survives as a shape-compatible shim. `GET /api/ops/scope-drift` consumes `snapshot()` when the service is wired and runs the same resolver over the stored blob when it is not (asserted to agree), and reports `alias_entries_rejected` + `alias_table_version` in **`data.summary`** (computed inside `buildScopeDrift` from the same coverage — deliberately NOT duplicated into `meta`, which carries only the accepted-entry count `alias_table_entries`, so each number has one source of truth). This sentence said `meta` until WS0 and was wrong from the start: `docs/ops/scope-derivation-migration.md` curls `.data.summary.alias_entries_rejected`, and a reader following the old wording would have found `undefined` and read it as "no rejects". `buildScopeDrift(aggregates, coverage)` takes an `AliasCoverage` rather than a bare record, so a hand-rolled table cannot satisfy it. `scripts/ops/migrate-scope-aliases.ts` migrates accepted pairs only via the exported `acceptedPairs()` and **refuses to run** when any entry was rejected unless `--allow-rejects` is passed (migrating rows under a mapping the server ignores just puts them back into drift).

**The anti-drift net is `tests/unit/scope-definition-composition.test.ts`:** one malformed table, and the resolver, the write path, the drift detector and the migration driver must all reach the same verdict on every entry — including the assertion that a variant is reported `aliased_to` **iff** `canonicalize()` actually moves it. If a future change gives any consumer its own parser again, that suite fails. This is the pattern the meta-finding asks for, not a scope-specific patch.

**Case-sensitivity regime: `alias-mediated`** (`SCOPE_CASE_REGIME` in the resolver). Case variants are equated by the alias table and by nothing else; resolution is exact-string in both directions. The drift detector's `slugifyScope` fold is a DETECTION aid and is many-to-one (`a_b`, `a.b`, `a-b` collapse), so it must never feed resolution. **Known exception still in place:** three sites per backend fold case in SQL (`COLLATE NOCASE` in `queries.ts`, `LOWER(...)` in `pg-queries.ts`) — which is why the migration driver needs its client-side exact-case filter. Removing the fold is gated on `active_rows_adrift` reaching 0 on live; while rows still sit on un-tabled case variants the fold is the only thing keeping them reachable. `tests/unit/scope-case-regime.test.ts` pins the current per-layer behaviour so the fold cannot disappear silently.

**One definition of "archived":** `is_archived` DEFINES archived state; `archived_at` is a companion stamp the two store methods keep in step. They nonetheless disagree on 58 live rows (active rows carrying a stale stamp from an older path), so a query written against `archived_at IS NULL` silently returns the wrong set — a trap hit twice here, once propagated to a subagent as established fact. Read archived state through `isArchived()` / `ARCHIVED_SQL_PREDICATE` (`src/utils/archived.ts`). `npm run reconcile:archived` is READ-ONLY: it reports the divergent rows and emits reviewed SQL for the operator to run in the container (copy first) — there is no endpoint that sets `archived_at` independently, so this cannot be an audited API migration.


### Scope Registry & Minting (Phase 3)

T46/Phase-1 clean drift up *after* it lands; Phase 3 prevents it at the source. A **`scope_registry` table** (SQLite migration v9 / PG v11; `IScopeRegistryStore` on both backends — `scope-registry-queries.ts` / `pg-scope-registry-queries.ts`) records durable per-scope state: `scope` (canonical storage form, PK), `slug` (the collision-detection key), `claimant_raw` (the string that first claimed it), `origin_cwd` (claiming directory when known — observation metadata carries cwd; direct API writes don't), `status` CHECK `provisional|confirmed|quarantined`, `reserved` (system scopes a mint can never claim), `ruled_distinct_at` (T76: set by the `mark_distinct` ruling — a RELEASE, not a status reading; see Visibility + rulings, below), `deferred_at` + `deferred_note` (blocker 4: the operator has SEEN this scope and postponed the judgment — bookkeeping, never a ruling, and read by the drift report only; the minting and hold paths ignore both columns). The registry **never auto-flips a status** — rulings are operator actions. `ScopeRegistryService` (`src/services/scope-registry.ts`) mirrors the `ScopeAliasService` posture: cached snapshot, invalidated on registry write, **fail-open to pass-through** — a registry read failure never blocks a write or recall (`tests/unit/scope-registry-service.test.ts`). Visual companion: mermaid flow in `docs/scopes/minting-flow.md`. (An interactive HTML twin lives in `docs/resources/`, which is excluded from the public cut — the mermaid doc ships in its place, so this pointer is expected to resolve only in the private tree.)

- **The minting decision** (`decideMint` in `src/scopes/minting.ts` — pure, no I/O/clock; the caller owns the registry read and the register write) runs inside the T46 `canonicalizeScope` choke point, alias table first. **Executable rule order** (deliberately differs from spec §5's narrative — pinned by `tests/unit/scope-minting-decision.test.ts`): global (never registers, R-D) → malformed (`isScopeForm` fail → reroute, R-C) → ephemeral (`ephemeralReason` **imported** from drift.ts, never re-derived — never mints; discovery holds these upstream, direct writes pass raw unregistered) → **claimant+origin exact pair** (hoisted BEFORE the canonical check so a quarantined claimant whose raw is byte-identical to the incumbent canonical re-resolves to its own quarantine scope instead of merging) → registered canonical (no origin = deliberate explicit write, the normal MCP `store_memory` case → pass; different origin + differently-named incumbent → **quarantine** `<canonical>--q<n>`, R-A: writes land and stay separate, never blocked, never merged) → known claimant unique (resolve — the claimant string is primary identity, a moved origin still lands home; multiple rows → fail-open pass) → new scope (slug collision → quarantine off the incumbent; else **mint**: slug form adopted as canonical storage for both prefixes, registered `provisional` with claimant+origin). Slugify **proposes and detects; it never merges** existing scopes — that stays the alias table's job. **Never-delete invariant (round-2 A1):** quarantine-suffix counting (`nextQuarantineN`) is collision-free ONLY because registry rows are never deleted — renames tombstone, and **no sweeper/GC exists anywhere**; any future registry delete must first switch to max-suffix derivation. **The alias-first composition is ONE exported function (round-2 A3):** `resolveWriteThroughAliases` (`src/services/scope-registry.ts`) — alias table canonicalizes first, then the registry decides — used by `resolveWriteScope`, the redrive route's `resolveTo`, the discovery scheduler's `resolveScope` closure, and the done-when suite's mirror; never hand-rolled (the one hand-rolled site was the final-review Critical). A mint/quarantine `register()` that loses a concurrent race (returns false) reloads the snapshot and re-decides ONCE, then fails open to raw (round-2 CO2).
- **Write-path routing** (`resolveWriteScope` in routes.ts, all five write sites; absent services ⇒ identity): the old `z.string().default('global')` silent leak is REMOVED. Scopeless writes land on the primary scope — **alias-canonicalized where it is LOADED** (`ScopeRegistryService.resolvePrimary`, round-2 CO1), so the scopeless default, decideMint's malformed reroute, and `buildMintContext` all see ONE canonical value (the fix-round-1 routes-only canonicalization fragmented the two triage paths) — else on **`project:_unrouted`** (reserved + `confirmed`, seeded idempotently at boot), **never `global`** (R-D; pinned by `tests/unit/scope-write-routing.test.ts`); response carries `meta.scope_defaulted`. Malformed explicit scopes are **captured, never 400** (R-C — supersedes the plan's "refuse"): rerouted the same way with the raw preserved in `metadata.raw_scope` and `meta.scope_rerouted {raw, stored_as, reason}`; the batch envelope aggregates per-class `{count, last}`. `project:_unrouted` is invisible to cross-project recall by construction (recall's only cross-scope fallback is `global`, which these rows never touch). Primary scope: `PRIMARY_SCOPE` env with the `operator_config.primary_scope` **column** taking precedence (column-targeted like `reasoner_provider`; PATCH validates `isScopeForm`, `null` clears). Discovery threads the same resolution via the engine's `canonicalizeScope` option; raw `project_scope` stays on candidates and run rows (lineage untouched).
- **Honest watermarks + held runs (spec §6):** `discovery_runs` gains status `'held'` (PG: the v11 constraint swap; SQLite: the observations DB has no migration ladder and a CHECK can't be ALTERed, so `ensureHeldStatus` in `observations-db.ts` rebuilds the table in place when the stored CREATE lacks `'held'` — idempotent) — when the engine skips an ephemeral scope it writes a `held` row stamping that scope's **own** max observation id, and every per-scope run row now records per-scope-honest end ids, not the global batch end. **Two watermark predicates, deliberately different, as named constants** in `src/database/interfaces.ts`: `GLOBAL_WATERMARK_STATUSES ['completed','held']` (the live-path cursor advances over a held burst — no starvation/refetch-forever) vs `SCOPE_WATERMARK_STATUSES ['completed']` (a held scope reads watermark 0 until its first re-drive completes, so re-drive sees its entire history). The stores build their SQL from the constants — no literal status strings; the divergence-exactly-on-`held` is pinned by `tests/unit/discovery-watermarks.test.ts`. Every existing run-row consumer includes/excludes `held` **deliberately, with the choice asserted** (`tests/unit/held-run-consumers.test.ts` — e.g. `/api/discoveries/runs` shows held rows by design; `getActiveRun` and the watermark readers don't).
- **Normalize-before-grouping (spec §9):** each observation's scope resolves ONCE at cycle start — through the SHARED `resolveWriteThroughAliases` (round-2 A3; registry-only resolution would quarantine tabled variants instead of pooling them and mint slug rows on ruled-away scopes), minting applied; the held short-circuit runs the SHARED hold predicate first (below); detection **groups on the resolved scope** so alias-variant evidence merges toward the occurrence bars, while **raw stays lineage** — observation rows untouched, one run row per member *raw* scope with its own per-raw end id (`tests/unit/discovery-normalized-grouping.test.ts`). The per-candidate store-time `canonicalizeScope` remains as belt-and-braces.
- **Hold + purge exemption are ONE predicate (spec §7; round-2 CO5+S1a):** a scope is HELD iff **ephemeral-shaped (`ephemeralReason`) AND not alias-mapped** (`canonicalize(raw) === raw`) — `buildHoldPredicate` in `src/discovery/hold.ts`, wired into BOTH the engine's held short-circuit and maintenance §1's exemption (absent closure ⇒ shape-only back-compat for unit stubs; canonicalize failure ⇒ held, the safe side). The alias entry IS the release: after a ruling, new observations on the ephemeral raw resolve to the target scope and its aged rows **return to the normal retention clock** — no more held-forever/exempt-forever divergence from the spec's §7 wording (`tests/unit/hold-predicate.test.ts`, `tests/unit/purge-exemption.test.ts`). **T76 §5.3/§5.4 add a second release path and a stricter caller:** `holdVerdict` (`src/discovery/hold.ts`) is now the ONE verdict function — held iff ephemeral-shaped AND not ruled-distinct (`ScopeRegistryService.isRuledDistinct`, released by the `mark_distinct` ruling — the scope stays itself, no alias entry needed) AND not alias-mapped — with two wrappers: `buildHoldPredicate` (loose, fail-TOWARD-holding — the discovery/maintenance consumers above) and `buildStrictHoldPredicate` (fail-CLOSED — the archive-ephemeral route's eligibility, below, where a swallowed read failure would silently AUTHORIZE a bulk archive instead of refusing one). **Accepted trade-off (operator ruling R-B):** an UNRULED ephemeral scope holds its observations indefinitely — no auto-expiry; the operator rules (alias entry) + re-drives to release. `purgeOlderThan(days, batch, exemptScopes?)` on both backends; the SQLite exemption loads a temp-table anti-join in 500-row chunks (round-2 S1b) so an exempt set past the bound-parameter cap can't kill the whole purge (PG uses `ANY($1)`, no cap issue); reported additively as `MaintenanceResult.observations_exempted_scopes`. Documented, not fixed: age-based purge can still delete a never-processed observation of *any* scope if ingestion outpaces detection past retention (pre-existing, recorded follow-up).
- **Time-preserving re-drive (spec §8):** `POST /api/admin/discovery/redrive {scope}` — admin-keyed, consolidation-lock-aware (423 busy), **409 while unruled** (refuses unless the alias/registry resolution actually moves the scope OR a `confirmed` registry row blesses it as-is, naming what's missing). **Structural invariant: a re-drive creates no observation rows and rewrites no timestamps** — spans compute from stored `started_at` (pinned expected `observation_span_days` in `tests/unit/discovery-redrive.test.ts`). Completion writes a normal `completed` run row under the raw scope, so the per-scope watermark advances and a second re-drive is a no-op. **Global-watermark bound (final-review I2):** a re-drive captures the GLOBAL watermark at start and only RE-COVERS ids at or below it (ids the live path already consumed via completed/held rows), so its run rows can never advance the global cursor past OTHER scopes' unprocessed observations — newer held observations wait for their next held row + a later re-drive, and a re-drive before any live pass is a clean no-op (empty result, no run row). The route's confirmed-as-is escape hatch **excludes reserved rows** (round-2 CO3): a tombstone or `project:_unrouted` is confirmed as system state, not operator-blessed for minting — re-drive refuses them with the 409 (`tests/integration/scope-minting.test.ts`). Known deferred minor: the route's `resolveTo` probe can mint a provisional registry row for an unknown non-ephemeral scope before refusing (spec-inherited; note the stray provisional **persists** — registry rows are never deleted and no sweeper exists (round-2 A1) — until an operator ruling; fix needs a peek-not-mint resolve variant).
- **Visibility + rulings (spec §12):** `GET /api/ops/scope-registry` (public — `tests/unit/ops-scope-registry.test.ts`): rows (**capped at 500** with `meta.truncated`/`row_total`; counts stay full-registry), per-status counts, held backlogs from run rows (**pending vs total** since round-2 CO6: `observations_pending` counts only held rows above the scope's completed per-scope watermark, and a fully re-driven scope drops out — held history stays in `/api/discoveries/runs`), `unrouted_active_rows`, `rerouted_rows` (count of active rows carrying `metadata.raw_scope`). The endpoint rides the shared 60s ops memo (round-2 S2); rulings delete the memo key so they reflect immediately, mints are at most 60s stale. `POST /api/admin/scopes/rule {scope, action: confirm|merge_into|rename|mark_distinct|defer|undefer, target?, note?}` (admin-keyed, `tests/unit/scope-ruling.test.ts`, `tests/unit/scope-deferral.test.ts`): **reserved rows (the triage seed, rename tombstones) refuse every ruling with a 400 naming them** (round-2 CO4 — renaming a tombstone would free its quarantine suffix, the exact R-A merge it prevents); **every ruling confirms the ruled row** (spec §12 bound over the brief's pseudocode — rename confirms the claimant under the operator-chosen target), and the confirming status write runs INSIDE the serialized chain (final-review M1) — a store failure after the alias entry landed is a 500 NAMING the partial state (alias live, row unconfirmed) and the `confirm` retry that heals it, never an unexplanatory 500; likewise a **blob-write failure after a rename's re-key + tombstone landed** is a 500 naming THAT partial state and the one recovery that works — PATCH the full `scope_aliases` map, never a rename retry, which would 409 off the tombstone (round-2 CO7). `rename` also **TOMBSTONES the freed scope** (final-review I1): a reserved+confirmed row under the ORIGINAL claim slug (claimant_raw = the freed scope itself), so bySlug counting never re-mints a freed `--q<n>` suffix for the next colliding claimant — whose rows would match the freed scope's alias entry and sweep into the renamed claimant's project (the R-A cross-claimant merge). `merge_into` validates + appends the alias entry through the serialized `configPatchChain` against the SHARED `buildScopeResolution` — the would-be table must accept the new entry AND not flip a previously-accepted one (the Phase-1 watchdog failure class) — and **auto-registers the confirmed target** so the target's next write can't slug-collide into quarantine. `global` is refused as a target (400); a raced rename PK conflict maps to a deterministic 409 on both backends; the response `meta.follow_ups` names the migration driver + re-drive commands verbatim — never run behind the operator's back. **T76 §5.2 (F-4): register-then-rule.** The 404 used to fire BEFORE the action branch, so a ruling on a scope with no registry row (most drift variants predate the registry) dead-ended; now an unregistered SCOPE-FORM scope is minted a provisional row (`claimant_raw` = the scope itself, no origin) in the same request before the ruling proceeds — a non-scope-form string still 404s, since there is nothing rulable to register. **T76 §5.3: `mark_distinct` is a fourth ruling.** It writes the dedicated `ruled_distinct_at` timestamp (not a status reading — every ruling already confirms the row, and status alone can't carry "distinct", T-C1) and releases an ephemeral scope AS ITSELF, no alias entry or rename required. That release reaches four consumers by TWO different mechanisms, and the difference matters when reasoning about a scope that holds a registry row it was never ruled on. Three of them read `ruled_distinct_at` itself: the hold predicate (`holdVerdict`, above), the archive-ephemeral eligibility check (below), and the drift report's `clusters_ruled_distinct` summary field plus each cluster's and ephemeral entry's own `ruled_distinct` flag (per-VARIANT since the cascade review, so a panel can tell WHICH member of a partially-ruled cluster was ruled instead of only whether all of them were). **Minting does not read the column at all** — `decideMint`'s ephemeral short-circuit is released by REGISTRATION (the T77 registry-aware guard above: a raw the registry already knows, as a claimant or as a canonical, falls through to the normal resolution rules), so `mark_distinct` releases minting through the registry row that register-then-rule guarantees, not through the timestamp it writes (`tests/unit/ruled-distinct-composition.test.ts` pins one seeded scope through all four, ephemeral and casing-cluster alike). **A successful `merge_into` SUPERSEDES a prior `mark_distinct`** (Codex round-2): once the alias entry lands, the handler clears that scope's `ruled_distinct_at` via `IScopeRegistryStore.clearDistinct` (both backends; unconditional and idempotent — a read-first guard would only add a way to be stale), because a row reading alias-mapped AND ruled-distinct is contradictory residue: the alias wins everywhere a decision is actually made (`holdVerdict`, the write path, recall), so the stale stamp only misleads the registry view and the drift panel, whose per-variant buttons filter on it. `ruled_at` is deliberately kept — the row WAS ruled, twice. A `clearDistinct` failure after the alias landed is a 500 naming that partial state and pointing at the idempotent merge_into retry, same posture as the confirming status write. No new MCP tools this phase (rulings are rare operator actions; curl/admin suffices for the preview). **Blocker 4 (deferral marking): `defer` / `undefer` are the two actions here that are NOT rulings** — they write the dedicated `scope_registry.deferred_at` + `deferred_note` columns (SQLite v14 / PG v16; plain nullable `ADD COLUMN`, the `ruled_distinct_at` shape) and deliberately do **not** confirm the row, because a deferral postpones the identity judgment that every status value asserts. `note` (≤500 chars, refused past the limit rather than truncated) is accepted ONLY with `defer` — its one storage home is `deferred_note`, so accepting it elsewhere would silently drop an operator's stated rationale. The drift report derives `cluster.deferred` (true iff EVERY unruled uncovered variant is deferred — the `ruled_distinct` arithmetic, and the non-empty requirement keeps the two aggregates disjoint), per-variant `deferred_at`/`deferred_note` on both row kinds, and the summary counter `clusters_deferred`. **The exclusion is ADDITIVE and that is the whole point (SYNTHESIS §1.2a — silently vanishing rulings are how watchdogs go dark):** a deferred cluster leaves `clusters_actionable` but stays in `clusters_uncovered` with its rows still counted in `active_rows_adrift`, so deferring can never silence the drift metric or hide the rows, which stay visible carrying the operator's own note. Any real ruling supersedes a deferral — `markDistinct` clears it in the SAME statement on both backends, `merge_into` clears it beside `clearDistinct` under the existing partial-state error path — and the inverse is refused: `defer` on an already-ruled-distinct scope is a 400, so no row can ever read both. `readRegistryMarks` (routes.ts) takes ONE registry snapshot per drift request and builds both `DistinctRulings` and `DeferredMarks` from it — two independent reads could disagree across a ruling that lands between them — fail-open to EMPTY/EMPTY (drift over-reported, the safe side). Note the one durable side effect a deferral shares with every other action here: register-then-rule mints a `provisional` row for an unregistered scope-form scope, and registry rows are never deleted, so `undefer` clears the marks but leaves that row behind (the response `meta.note` says so).

- **Bulk archive ephemeral scopes (T76 §5.4, Tasks 6/7):** `POST /api/admin/scopes/archive-ephemeral {scope, apply?: false}` (admin-keyed) bulk-archives an ephemeral scope's active rows once no release (alias entry or `mark_distinct`) has been ruled. Eligibility runs through the SAME `holdVerdict` predicate as hold/purge (T-H4: never a fifth spelling of "held"), but through `buildStrictHoldPredicate` — fail-CLOSED, so a broken alias-table or registry read REFUSES the archive (503) rather than authorizing one. Dry-run is the default (`apply` must be explicitly `true`); a real run acquires the consolidation lock (`uniqueHolder('scope-archive')`, 423 when busy) and pages the scope's active rows in 100-row chunks up to a 500-row cap per call (ruling L-4 — repeated calls are the designed drain). **F-7 mid-call version stop:** each chunk re-reads the UNCACHED alias table (`readScopeResolutionStrict`, bypassing the 60s `ScopeAliasService` cache) and re-checks eligibility before archiving further; a version change or a lost eligibility check stops the call and returns the partial result (`stopped: 'alias_table_changed' | 'eligibility_changed' | 'resolution_read_failed' | 'store_read_failed'`) instead of either archiving past a ruling that just landed or discarding already-archived rows behind a thrown 503. The split is POSITIONAL, not outcome-based (F-9): pre-loop reads THROW (they run before any archive is possible), every in-loop read REPRESENTS — the F-7 re-check and the page fetch itself (`store_read_failed`) both stop and report, so a first-chunk page-read failure returns a truthful `archived: 0` with its reason rather than a 503, and that also holds in dry-run (the guard is not gated on `apply`). Every archive runs through `auditedArchiveMemory` under a new audit-only `archive_ephemeral` class (see the `DreamDiffClass`/`DreamAuditClass` split, below) on one `CarrierDream` per call opened with `trigger_source: 'manual'` — the ONE write site that stamps `dreams.is_carrier = true` is `CarrierDream.open()` (F-5/T-H3/T-M6: a persisted column, not reason-string matching, excludes carriers from `getLastCompletedDream`/`listPendingDreams` while `listRecentDreams`/dream-history still include and label them); `finalize()` runs in a `finally` so the dream row stays truthful on any abort. No dream store wired ⇒ WITHHOLD, never a bare archive (mirrors maintenance §2's posture). The response carries `dream_id` (the carrier, and the pass's rollback handle), `archived_ids` (the ids actually archived — rollback is PER-MEMORY and the rows are already archived by the time the operator reads the response, so this list is the undo enumeration; empty in dry-run, naturally capped at 500) and `alias_table_version`; failures land in a capped `failed[]` (20 entries) with `failed_total` reconciling the count past the cap, and each failed attempt still counts toward the carrier's `memories_examined` (rows ATTEMPTED); a `finalization_failed: true` flag reports a carrier `finalize()` that threw — the archives stand and are individually audited, but the carrier row never reached `completed`, so every counter-based view of that pass under-reports it; a page is filtered to the EXACT requested scope spelling before archiving (`list`'s own scope match is case-insensitive, but eligibility is exact-string under the alias-mediated case regime — a case-twin row is skipped whole, not silently swept in). Core logic lives in `src/scopes/archive-ephemeral.ts` (`runArchiveEphemeral`, unit-tested without HTTP); the route (`src/api/routes.ts`) is a thin schema-parse + lock + error-class-to-HTTP-status wrapper.
